# 提示词与上下文

[文档目录](README.md) · [按主题拆开的详细说明](GUIDE.md) · [返回 README](../README.md)

主回复使用 AstrBot 原生 Agent。本插件追加角色处境，保留宿主历史、工具和其他插件注入。

## 她看得到什么

一次群聊请求里，她看到的东西由三层拼起来：

1. **宿主原生的上下文**：真实对话历史（`req.contexts`）、用户这一条消息、工具清单与工具说明。
2. **本插件注入的稳定层**（写进 `system_prompt`）：她的人设、世界规则、怎么说话、当前场景。
   宿主的 `# Persona Instructions` 会按原文精确摘掉，其它插件写进同一个字段的内容一个字不动。
3. **本插件注入的易变层**（写进 `extra_user_content_parts`，跟着用户消息走）：
   状态、位置、正在做的事、记忆、最近聊天背景、画像、最近发生的事、临时提醒。

易变层**不写进对话历史**：它只对当前这一轮有效，所以不会把"她昨天心情不好"固化进上下文。

## 按当前事情选择背景

从 v4.32 起，小世界自己的动态背景由统一选择器组装。它先检查来源会话、人设和有效期，再按当前任务、话题、实际说话人、未完事项与发生时间选择材料。先覆盖相关事情的概要，有必要且篇幅允许时再展开细节；单条依据作为整体保留，不截掉否定、条件或后续结果。

| 当前任务 | 优先提供的材料 |
| --- | --- |
| 普通回复 | 当前对象的身份与关系、有关经历和约定、正在延续的话题、此刻状态 |
| 旁听接话 | 目标群现场、相关参与者与经历、少量此刻的生活背景；不固定带地图和动作库 |
| 自主规划 | 正在做的事、未完生活事项、可达地点、能力与安排 |
| 定向表达 | 发言落点的聊天现场、实际对象、有关生活进展与经历 |
| 事件与结算 | 当前事件完整的来龙去脉与结果依据，再补相关生活背景 |
| 自主作息 | 真实疲劳、睡眠记录、日程与未完事项，避免用无关群聊拖延休息 |
| 日记、画像与睡眠整理 | 保留该任务已确定范围的原始证据，不通过相关性排序丢弃修正或前因 |

例如“今天好多了”会结合这个人前面说过的事检索，而不是只搜索这几个字；聊到旧风车时，即使她已经换了地点，也能找回相关经历。梦境、主观感想和世界内准备分别带来源说明，不能当成亲历事实或现实操作回执。

私人约定只在来源会话且对象实际参与本轮时使用，不作为共享的自主规划或日记动机。同一生活组中其他会话的近期活动可按原有设置作为带来源标记的背景；旁听接话只读取目标群。记忆共享范围仍服从既有记忆设置，选成“手动回忆”后不会自动检索。

选择不增加额外的 LLM 判断调用：默认用结构化信息与文字匹配，已开启语义记忆时沿用语义结果，语义服务不可用时保留文字检索。缺少依据时允许不确定，不补造记忆。已知必须一起理解的材料会整体保留，即使因此超过普通背景的软字数额度。

正式请求、预览和隔离测评共用构建逻辑。实际请求快照、决策记录和测评结果会带 `context_selection`，可查看选入或略过的原因、概要/细节视图及字数；筛掉的其他会话私密材料正文不会写进选择记录。预览和测评不会增加记忆召回计数，也不会发送群聊消息。

这一选择器只处理小世界提供的材料。宿主的原生历史、工具结果、图片与其他插件注入仍由各自管理，因此不保证整个请求总是更短，也不替换 AstrBot 的历史压缩。

## 群聊上下文怎么存、怎么带

她不是靠"每轮把整个群聊塞进去"：

- 收到的每条消息会进本插件的聊天留档（谁、什么时候、@ 了谁、引用了什么、图几）；
- 留档带**水位线**：哪些已经回过、哪些还没回；没回报过的消息下一轮才需要出现；
- 渲染成提示词时分三段：容易变的（这一轮要回的）给足字数，背景与别处听到的收紧字数；
- 她自己在群里说过的话也会记回去，所以下一轮能看到"我刚刚说过什么"，避免复读。

## 图片

图片有两个来源：用户这一轮发的图，以及聊天留档里最近的图（有上限）。

原生 Agent 会按 AstrBot 自己的规则处理图片（多模态直读或走转述模型）；
本插件只把"图几、跟谁有关、在哪条消息里"这类**注解**写进自己的处境层，
不改 `req.image_urls`，也不吞别的视觉插件（如 `motion_vision`）加进来的帧与解读。

## Token 预算与缓存

提示词按"越稳定越靠前"排：

- 人设 / 世界规则 / 说话格式 / 当前场景：基本不变，放在 `system_prompt` 前部，吃宿主的前缀缓存；
- 状态 / 记忆 / 聊天背景 / 提醒：每轮都变，放在**最后**的附加块里，
  不会把它们前面的固定前缀一起打成缓存未命中；
- 声音样例这种"每轮轮换"的内容放在最末尾，靠近这一轮的实际输出。

各项额度（聊天每行多少字、留多少条、记忆给几条、图给几张）在编辑器「全局设置 → 上下文」里调。自动选择沿用这些设置；内部按任务分配软字数额度，不新增“完整/精简”开关。被引用的原消息链和任务必需证据可以超过普通背景目标，避免只留下没有前因的结论。

## 别的插件给的上下文

只追加、不替换：

| 通道 | 本插件的处理 |
| --- | --- |
| `req.system_prompt` 里别人的内容 | 原样保留（只摘掉宿主那份 persona） |
| `req.extra_user_content_parts` | 原样保留，本插件往后面追加自己的处境块 |
| `req.contexts` / `req.image_urls` | 不动 |
| `req.func_tool` | 不动（工具循环归原生 Agent） |
| 老版本里被拼进 `req.prompt` 的临时信息 | 不动，原样交给模型 |

## 短期聊天窗口

My World 只保留有限的近期消息，供本轮回复、画像提取和关系判断使用。超过条数上限时移出最早消息，不生成滚动聊天摘要，不将聊天写入生活库。聊天长期记忆由 Anamnesis 等专门插件管理；AstrBot 自身的对话历史与压缩设置仍由宿主控制。
