# 安静翻消息

[文档目录](README.md) · [生活工作区](life-workspace.md) · [与 Anamnesis 配合](memory-compatibility.md)

她可以在空闲时拿起手机，或在有电脑的地方看看近期消息。每次成功读完都会留下 **她自己的想法**，可以是简短、平淡的反应，不要求强烈情绪或总结群聊；是否接话再由她自己决定。

例如，别人聊到窗边开花，她可能想到“也想在自己的窗边慢慢养一盆”；这只是一点个人感想，不代表她已经买了花，也不会自动替她创建任务、许下约定或发消息。

## 怎样开启

1. 打开 **生活**，点击页顶的 **手机与电脑**。今日、牵挂和经历三个视图都能直接打开。
2. 开启“空闲时可以安静翻消息”。这项功能默认关闭。
3. 按原有人设选择“她有一部手机”，或勾选有电脑的地点。未提供设备时不会安排这项活动；电脑只在所选地点可用。这里的设备属于角色世界，不需要服务器电脑、浏览器或沙盒。
4. 按需要限制可翻阅的会话。不选表示同一共享生活组内已启用的会话；选择后仅使用所选范围，不跨生活组。
5. 点击“应用设置”，再点顶栏“保存”。有独立生活配置时，先在顶栏选择相应编辑范围。

开启后，最短间隔结束、有未读消息时，她在下一个合适空闲开始浏览，不再额外做随机抽签。睡眠、困意、低精力、日程与重要经历优先；有未完动作或计划时先做手头的事。关闭“自主发言”后，这项安静活动仍可进行。插件或实际来源会话停用后，不再读取相应内容。

**120 分钟表示两次开始浏览至少相隔 120 分钟，不是每两小时定时浏览。** 没有新内容、没有设备、正在休息或忙碌时都会等待。开始次数包含中断与生成失败，成功读完必须有非空想法和有效阅读依据。在 **内心活动 → 翻消息时** 可看今日开始次数、本会话最近读完时间、最早可再浏览时间与当前等待原因；共享生活组会明确标注共用次数。

## 她能看到什么

只使用 **插件实际收到并仍在近期窗口内的文字**。一次读取一个实际会话，不向平台补拉历史，不访问服务器文件或调用电脑工具。阅读感想阶段的图片只显示 **「图片」** 占位符，纯图片消息也会留下占位；不传图片、图片地址或已有识图转述，不因此识图或下载资源。带图消息保留发送者自己写的文字；无法确认原文的旧带图记录只显示占位。她知道有人发过图，但不能凭空猜测画面。

| 默认限制 | 数值 |
| --- | --- |
| 阅读窗口 | 最近 12 小时，可设为 1–24 小时 |
| 每次消息数 | 最多 500 条，可设为 1–1,000 条 |
| 每次正文总量 | 最多 60,000 字，可设为 300–120,000 字 |
| 两次浏览间隔 | 至少 2 小时 |
| 每天浏览次数 | 默认每个角色最多 3 次，可设为 1–100 次，共享生活组共用额度 |

条数与字数同时生效，先到哪个上限就停；消息不足时不会凑数。进入 **手机与电脑 → 每次读多少** 可直接调整，也可“恢复推荐量”。仍使用整套推荐阅读值的旧配置会自动采用推荐量；单独调整过的阅读设置保留。

开启后复用已有短期缓存，每个会话至少保留配置的消息条数，无需再改普通聊天的留档设置。扩容不能补回已经裁掉的消息；普通聊天带入提示词的行数和字数仍按原设置控制。单条原文沿用短期留档的长度限制，图片占位也计入阅读字数。

浏览占用约三至八分钟的角色生活时间，收尾时完整携带当前人设，通常请求一次判断模型，输出限制为 600 Token；判断通道失败可能按现有规则回落。读取量越大，单次输入与 Token 消耗越多，可能受所选模型的上下文容量限制。消息字数上限不包含人设，长人设也会计入后台预算。所有请求都使用已有后台并发、超时、退避和每日预算，不增加常驻服务或运行依赖。

浏览有自己的进度。她回过的内容仍可以在空闲时看看；看过的内容不会因此变成“已回复”。没有新内容或只有自己的消息时，不为浏览调用模型。新消息正常挤出旧缓存时，已经读到的这份内容仍可完成感想；手动清空上下文则取消本次浏览。失败或被打断仍保留本次冷却与次数，避免连续重试。

默认开启 **阅读时参考已有关系与兴趣简述**：按消息的实际发送者身份，只读来源会话的已有关系档位、画像简述和兴趣，最多 6 位实际作者、总计 1,200 字。没有稳定身份或资料就不猜；不额外提取画像、不改变好感度，不把摘要当成本次发言或共同经历的证据。可在手机与电脑设置中单独关闭，画像总开关关闭时也不加入。

## 感想留在哪里

- **生活 → 今日** 显示正在翻消息的活动。
- **内心活动 → 翻消息时** 单独显示每次成功阅读留下的想法、地点和来源会话，不混入“心里的话”；“阅读依据”默认折叠，只保留至多两段短片段供核对，并标注是否实际接话。空想法、超过 120 字或缺少有效依据的结构化结果只补生成一次，仍失败就明确显示原因，不推进完成进度、不编造想法。补生成仍使用后台预算；请求失败或预算拒绝时不追加调用。清空按钮只清当前子页，不重置浏览进度。旧版已读但未记录的想法不追补。
- **模型调用** 可按“翻消息时的感想”筛选，查看原因、结果和 Provider 返回的用量。

普通感想在最近 24 小时内可作为相关对话的参考，到期后不再作为近期感受注入，但仍保留供历史查看，不因生活时钟或下次浏览而删除。“心里的话”和“翻消息时”合计保留最近 3000 条，默认显示全部日期，也可按世界时区选择日期，每次展开 40 条；未记录时间的旧条目单独显示，不猜测日期。清空会删除当前会话、当前分类所有日期的记录，确认框会明确说明范围。旧版已清理或超出保留范围的条目无法补回。

只有被判断为对自身生活有持续意义、且开启相应选项的感受，才进入生活记忆。记的是“翻阅消息时，我想到……”，保留来源与理由，不保存第二份聊天摘要。历史查看不会把普通感想变成长期记忆，也不会重新触发旧接话。

感想可以轻微影响当下心情，单次额外情绪偏移不超过正负 0.02；原有情绪仍照常随时间变化。它不会增加好感、改变身份关系、提取人物事实或词典，也不会改写人设、喜恶和价值观。

## 与正常聊天、聊天记忆的区别

| 机制 | 重点 |
| --- | --- |
| 正常聊天与回合复盘 | 对方正在与她交谈，回复后记录本轮实际互动。 |
| 安静翻消息 | 她在独处时阅读已有消息，只留下自己的主观感受。 |
| Anamnesis 等长期记忆插件 | 保存与检索聊天往事，帮助回答过去聊过什么。 |

已注入的 Anamnesis、RAG 历史记忆块会从阅读材料中剔除，不再当成新消息。人物事实、详细画像与群词典继续按各自原有机制工作。

浏览感想始终保留实际来源。**私聊感想只在原私聊被动交谈相关时参考**，同一生活组的其他群和私聊也不能召回它；群里的感想同样留在原群。普通自主发言、事件结算、角色审视、睡眠整理与自动回访不使用这类感想，不把它们放入主动话题或待发送队列。有意义的长期感想可在原会话的正常回复中相关召回，或通过 `mw_memory_lookup` 查询。

浏览输出只接受感想、小幅心情变化和来源编号。模型返回的发言、工具或任务指令都不会执行。中断、跨日、人设或配置变化、离开原地点、原消息已清除时，过期结果作废；已经开始但被取消的请求不会在重启后重放。清空当前会话上下文也会清掉它的短期浏览感想，生活记忆仍由记忆页面单独管理。

## 浏览后可选接话

在 **手机与电脑** 开启 **浏览后允许她判断是否接话**，默认关闭。它独立于“新消息到来后自然接话”开关，仍需要全局自主发言开启、实际来源会话进入主动发言白名单，以及该会话允许自主搭话。群聊或私聊分别核验；阅读权限、共享生活都不授予发言权限。无需开启生活分享。

读完后，另外用接话协议检查来源会话的当前现场，并参考 **本次刚留下的想法**，由她决定是否回应其中一条仍新鲜的消息，也可以继续旁听。这个想法不要求与聊天用词相同，也不依赖生活话题开关；它参与当前判断，不作为亲历或人物事实，不原样复述内心或突然汇报生活。自主判断始终允许旁听。只读到旧消息、话题过期、会话撤权或后台预算不足时不补话。同一批现场不反复判断，也不消耗主动找人额度；使用现有引用路径，与 OutputPro Split 的引用设置兼容。

遇到正在回复或手头活动收尾时，默认 **短暂忙碌最多等待 120 秒**，可设为 0–300 秒，0 保持不等待。等待与普通接话共用每个角色的收集器，等待本身不占模型工作池。结束占用后，重新核验原消息是否还有效，再做一次接话决定；不重新生成阅读感想、不提高随机概率。等待后的发言必须引用本次机会原有的消息，后来消息只帮助理解当前话题，不能借旧机会去回答新的消息。普通回复已回应原消息、其它接话已判断该现场、来源撤权、开始休息、清空、换人设、新阅读替代或到达截止时间时放下。进程重启不重放，展示也不会长期保留“正在等待”。

群聊中的开放分享和公共话题可以自然参与，有具体兴趣、感受或相关经历即可，不要求对方先点名或提问。只有“没人问我”不足以判断没有参与点；没有自己想接的内容、话题已结束或对方明确在等别人时，仍可继续旁听。

阅读想法已存在，发言决定仍须通过结构化校验。非空但无效的返回可按原有协议修复一次，继续复用同一份阅读想法，不重新阅读或编造内心；空返回不追加调用，连续无效结果停止。修复不重跑工具，保留第一次取得的工具结果；修复期间现场过期、感想清除或权限变化时不发送。修复可以保留旁听选择，不把格式错误当作必须开口。

接话请求未完成时，浏览记录保留本轮真实原因，例如原生上下文准备失败、模型不可用、后台预算或退避；已留下的阅读想法保留。调用失败不等于她选择旁听，也不等于模型返回了错误格式。格式修复请求失败时记录该次失败，空内容（包括只有空白）不追加调用。错误记录会隐藏密钥和请求地址，旧记录缺失的底层原因不能追补。

本次想法按阅读批次、来源会话与人设关联，放进原有上下文预算；同一感想形成长期记忆时不会在本次判断里重复出现。清空、过期、切换人设或后续阅读取代它后，不用旧感想重新触发接话。新记录的短期与长期感想都保存人设标记，换角色后不继续注入；旧版缺少标记的记录保留兼容，不能凭空推断它属于哪份历史人设。

浏览约占三至八分钟，因此浏览后接话保留最近 15 分钟的短暂回看范围，避免刚读过的消息到读完就自动过期。模型会看到消息时间与后续对话，判断话题是否仍适合接；问题已解决、话题已结束时可以放下，不追答数小时前的旧聊天。普通新消息接话仍使用原有时效。开启也不保证每次阅读都会接话。真实发送成功才标记“已自然接话”。

浏览记录中的“本次未进入接话判断”是当次保存的历史结果，不能当作实时进度，也不代表她已经决定不接话；新等待记录有明确截止时间和最终结果。接话发送后，感想和实际发言仍在原阅读会话中显示，共享生活组的非主会话也可查看和清空；已有阅读来源的旧记录同样适用。真实对话回复优先；被路由拦下或已释放的宿主事件不会继续挡住接话，无法观察到事件的旧登记只保留五分钟的回复预期。正在执行的回复准备单独跟踪，超过本次等待上限或已处理的旧现场不会在回复结束后追答。群聊标签与会话选择优先使用人工备注和平台真实群名；拿不到群名时只显示群号，不使用群友昵称。

正常 QQ 聊天依旧使用 AstrBot 原生 Agent、工具和发送能力。阅读感想与接话分别生成；阅读输出中的发言或工具指令始终不执行。日程和事件的发言仍受各自开关、主动发言及生活分享两份白名单控制。

开启浏览后接话时，接话阶段可按需查看本会话近期图片，并联动已启用的 Motion Vision 处理动图。媒体仅用于本次请求；阅读感想阶段仍按上述文字范围运行。资源、失败降级与发送记录见 [主动发言与内心记录](proactive-speech.md)。
