# 与 Anamnesis 共存

[返回 README](../README.md) · [记忆与通讯录](memory.md)

两个插件可以分工：Anamnesis 负责长期聊天记忆，我的世界负责角色自己的生活经历。两边同时运行时，请使用默认的 `reply_mode=inject`，并优先使用 Anamnesis 的 `extra_user_content` 注入方式。

## 会冲突吗

源码对比基于 Anamnesis 的 [18514fc](https://github.com/Whereis-Alice/astrbot_plugin_anamnesis/tree/18514fc72fbe74aae776167e83beb443d3e022d1)。它通过 AstrBot 请求钩子召回记忆，可以追加临时内容，也支持修改用户消息或构造工具历史。本插件默认只替换自身人设、追加当前处境，保留宿主历史与其他插件的临时内容，因此这条默认路径没有直接覆盖记忆的冲突。

但二者会做部分相同的事：

| 内容 | Anamnesis | 我的世界 |
| --- | --- | --- |
| 聊天长期记忆 | 混合检索、图谱关联、召回与反思等生命周期机制 | 将参与的对话压成简短摘要，按作用域、地点、相关人物和权重召回 |
| 角色独处的经历 | 主要依据其收集到的会话内容 | 直接记录动作、地点、事件、情绪与内心活动 |
| 自动注入 | 自己检索并注入 | 注入当前生活状态、画像和选中的记忆 |
| 数据保存 | 自己的记忆库 | 本插件的 SQLite 与画像目录 |

两边都保存聊天时，同一轮对话可能被总结两次；两边都召回时，记忆文本会相加。不同插件的数据库、索引和事实标识不通用，本插件不会擅自删除 Anamnesis 的内容，也不声称能跨插件识别所有语义重复。

这是源码兼容性分析与本插件的回归验证，未对所有 Provider、全部注入组合或未来版本做运行保证。旧版 `takeover` 会自行调用模型，建议迁回默认注入模式；特别是外部插件构造的工具历史，不应假定会被旧接管流程完整复用。

## 推荐设置

1. 在记忆库点 **记忆与共存设置**。
2. 选择 **与 Anamnesis 共存：只自动回忆生活经历**。
3. 按需要设置自动召回字符预算，默认 1200。
4. 应用后点击顶栏 **保存**。

此方案会关闭 `memory.dialogue_summary`，将 `memory.automatic_recall` 设为 `life_only`。本插件继续记生活，常规自动召回与到期回访排除聊天摘要。已有聊天摘要保留，可以在记忆库查看、导出和删除，也能通过主动查询取用。

若只希望在需要时取用本插件记忆，选 **不自动回忆，只在主动查询时取用**；当前生活状态与画像仍会提供给模型。`mw_memory_lookup(topic)` 可查询当前会话、共享生活组及明确全局记忆，不会因自动记忆设置为 `manual` 而失效。它按话题检索，最多返回 5 条和 6000 字符；没有命中时明确返回未找到。

设置使用顶栏的编辑范围。会话正在继承全局设置时，需要先开启“本页配置”，才能保存独立策略。共享生活组使用同一份生活配置。

## 上下文会增加多少

无法仅凭插件数量给出固定 token 数。一次请求的增量取决于两边实际召回的内容、画像和状态长度，以及模型的 tokenizer。

`memory.recall_max_chars` 限制本插件常规自动召回的完整文本行，包含日期、情绪与附带原文；超过预算的条目跳过，不截断事实，不修改数据库。默认 1200，范围 0～12000；0 表示不自动召回。自动召回还会合并同一天、同地点、相同参与者的重复文本，避免同一事实在多个作用域里重复出现。

这个预算不限制外部记忆、通讯录画像、状态、近期事件或回访内容。到期回访另受“每天最多回访几次”等配置控制；选择 `manual` 或预算为 0 时也会停用自动回访。需要核对实际请求时，请看调试页的提示词预览和请求快照。

## 当前记忆库的取舍

本插件的记忆适合短小、有地点和人物线索的生活经历。它已有睡眠整理、时间衰减、权重、回访和作用域控制，但没有把 Anamnesis 的向量／图谱检索搬进来。长时间、多话题的聊天知识建议交给专门的长期记忆插件。

这一版补上了自动召回类型与预算、重复事实过滤、严格话题查询、摘要长度控制，以及模型不可用时的来源标记。未来若需要统一检索，应通过明确的数据接口接入，保留原始来源与权限，而不是共享修改彼此的数据文件。
