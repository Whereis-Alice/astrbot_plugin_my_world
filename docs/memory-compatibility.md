# 与 Anamnesis 配合

[文档目录](README.md) · [生活记忆与通讯录](memory.md) · [数据与迁移](data-and-migration.md)

My World 构造她自己的生活，Anamnesis 记录聊天往事。两者可以一起使用，无需选择双份聊天存储模式，也不需要共享数据库。

## 各自负责什么

| 内容 | My World | Anamnesis |
| --- | --- | --- |
| 独处活动、作息、事件、生活事项 | 执行并记录实际经过 | 不负责推进生活 |
| 生活回忆、内心与梦 | 保存、整理和召回；梦明确标记 | 不自动接收这些记录 |
| 聊天往事的长期检索 | 不保存长期聊天摘要 | 由它保存、检索和注入 |
| 人物事实、详细画像 | 保留自动提取、结构化字段、工具与人工管理 | 可独立使用它自己的能力 |
| 好感、关系、相处习惯 | 按实际会话发展和管理 | 不接管本插件的关系计算 |
| 群词典 | 自动学习、人工维护、当前会话命中注入 | 无需移交 |

人物事实与详细画像来自心迹画像的集成能力，描述稳定资料；它们仍归 My World 管理。聊天往事描述过去说过什么、发生过什么，不再由 My World 建立第二套通用长期记忆。

## 怎样设置

1. 分别启用两个插件，并在各自页面设置模型和作用会话。
2. 在 **生活记忆 → 回忆设置** 选择自动回想生活或仅主动查询，调整字符预算。默认自动，预算为 1200 字符。
3. 人物资料在 **通讯录** 管理，好感和身份在 **关系与好感** 管理，共同用语在 **会话词典** 管理。
4. 生活整理与人物资料整理分别开关。关闭人物画像不妨碍她整理自己的生活。

共享生活组使用同一生活配置；不同实际会话的人际关系仍独立发展。要保存独立配置，先在顶栏选定编辑范围并开启本页配置。

## 模型怎样查询

- `mw_memory_lookup(topic)`：查她的生活经历，最多五条、6000 字符；查不到明确返回未找到。
- `mw_profile_lookup`：查人物事实、字段、备注与关系资料。
- 聊天往事：使用 Anamnesis 提供的查询能力，My World 不将请求转发到对方数据库。

关闭自动生活回忆或将预算设为 0 后，主动查询仍可使用。该设置也会停止生活记忆的自动回访，人物资料与词典仍按各自设置工作。

## 注入和开销

My World 保留 AstrBot 原生 Agent、工具循环和发送方式，不删除或改写 Anamnesis 注入的记忆块、临时消息或工具历史。它识别新旧记忆标记，避免把注入的旧回忆再次当作用户本轮原话提取事实。

两边没有统一的 Token 预算。生活回忆的字符限制只约束本插件常规自动召回，不包含人物资料、当前状态、事件、独立回访和 Anamnesis 的内容。请分别限制召回量，用提示词预览和模型调用页观察真实开销。

本插件可选轻量语义检索，先过滤会话范围再请求嵌入，失败时退回关键词。主动使用 `mw_memory_lookup` 时，还可在生活页设置中开启候选重排：最多十二条生活候选，额外一次判断请求，只调整顺序，不改写正文，也不查询聊天记忆。失败时使用原排序；返回前检查来源与内容是否已被修改。查询结果附记录编号、日期、来源和命中依据。普通聊天不会因此每轮增加重排请求；重要生活记录建议定期导出。

动态媒体由 Motion Vision 负责抽帧、音轨、字幕与回看。My World 保留其临时内容与原生工具，不延长帧或音轨的保存时间；已确认属于媒体插件的帧与动图来源不再交给普通看图流程重复转述。普通静态图仍保留宿主视觉与必要兜底。媒体内容是外部证据，不会作为用户原话或角色亲历写入生活库。

My World 不迁移、修改或自动同步 Anamnesis 的配置和数据库。旧聊天摘要迁出时保留本地完整备份，处理方式见 [数据与迁移](data-and-migration.md)。
