# 与 Anamnesis 共存

[返回 README](../README.md) · [记忆与通讯录](memory.md)

**可以两边都保留，也可以两边都保存聊天。** 推荐将“保存哪些数据”和“每轮提供哪些数据”分别设置：聊天历史由 Anamnesis 检索，生活经历由我的世界提供，稳定的人物资料由通讯录提供。这样保留两边的能力，同时减少每轮重复的背景文字。

两边同时运行时，请使用本插件默认的 `reply_mode=inject`，并优先使用 Anamnesis 的 `extra_user_content` 注入方式。

## 会冲突吗

源码对比基于 Anamnesis 的 [固定快照](https://github.com/Whereis-Alice/astrbot_plugin_anamnesis/tree/18514fc72fbe74aae776167e83beb443d3e022d1)。它通过 AstrBot 请求钩子召回记忆，可以追加临时内容，也支持修改用户消息或构造工具历史。本插件默认只替换自身人设、追加当前处境，保留宿主历史与其他插件的临时内容。连发合并需要替换本轮正文时，外部记忆会单独保留。

新旧 Anamnesis 记忆标记会与本轮直接发言分开，不拿来再次提取用户事实、评价好感或学习群梗。其临时内容与模拟工具历史继续留给原生 Agent 使用；两插件各自管理自己的注入块。

但二者会做部分相同的事：

| 内容 | Anamnesis | 我的世界 |
| --- | --- | --- |
| 聊天长期记忆 | 混合检索、图谱关联、召回与反思等生命周期机制 | 将参与的对话压成简短摘要，按作用域、地点、相关人物和权重召回 |
| 角色独处的经历 | 主要依据其收集到的会话内容 | 直接记录动作、地点、事件、情绪与内心活动 |
| 自动注入 | 自己检索并注入 | 注入当前生活状态、画像和选中的记忆 |
| 数据保存 | 自己的记忆库 | 本插件的 SQLite 与画像目录 |

两边都保存聊天时，同一轮对话可能被总结两次；两边都召回时，记忆文本会相加。不同插件的数据库、索引和事实标识不通用，本插件不会擅自删除 Anamnesis 的内容，也不声称能跨插件识别所有语义重复。

本地隔离测试执行了该快照的实际注入分支，覆盖前置、后置、临时内容、模拟工具调用四种方式，以及两种钩子先后顺序；另验证了连发合并不会丢掉前后记忆。没有连接生产实例，也未穷举所有 Provider 或未来实现。旧式 `takeover` 会自行调用模型，建议迁回默认注入模式；外部插件构造的工具历史不保证被旧接管流程完整复用。

## 选择适合自己的保存方案

在 **记忆 → 共存设置** 中选择方案，再点击顶栏 **保存**。这只修改本插件；Anamnesis 仍在它自己的配置中设置。

| 方案 | 本插件保存聊天摘要 | 本插件常规自动召回 | 适合谁 |
| --- | --- | --- | --- |
| **分工记录** | 停止新增，旧数据保留 | 生活经历 | 希望减少重复摘要调用与存储，推荐作为起点 |
| **双份保存** | 继续保存 | 生活经历 | 希望两边都有聊天记录，也保留各自的查询能力 |
| 自定义：全部记忆 | 可自行开关 | 生活与聊天 | 接受更多上下文和重复内容，愿意自行观察预算 |
| 自定义：只主动查询 | 可自行开关 | 不自动召回 | 希望模型在需要历史时再查 |

“双份保存”让两套记录独立积累，**不会自动互相复制、同步或补齐历史**。代价是两边可能各调用模型总结同一段聊天，增加调用与存储开销。选择它不会把字符预算重置；建议先用 800～1200，再观察实际请求。

这里的“保存”仍受各自的记忆整理和保留策略影响，不等于永久保存所有原始消息。本插件写入时有约 500 条的会话／人格容量整理，会清理低权重条目；需要长期留档的内容应另外导出备份。

### 分工记录

1. 在记忆页点 **共存设置**。
2. 选择 **分工记录：Anamnesis 存聊天，本插件存生活**。
3. 按需要设置自动召回字符预算，默认 1200。
4. 应用后点击顶栏 **保存**。

此方案会关闭 `memory.dialogue_summary`，将 `memory.automatic_recall` 设为 `life_only`。本插件继续记生活，常规自动召回、相应的嵌入候选与到期回访排除聊天摘要。已有聊天摘要保留，可以在记忆库查看、导出和删除，也能通过主动查询取用。逐轮互动评价、人物资料提取和睡眠整理是独立功能；本方案不会一并关闭它们，需要进一步减少判断调用时可在设置中分别调整。

### 双份保存

选择 **双份保存：聊天都记录，本插件只自动回忆生活**。它将 `memory.dialogue_summary` 设为 `true`，`memory.automatic_recall` 设为 `life_only`。聊天摘要照常累积，但不进入本插件的常规自动召回与到期回访。

模型需要核对历史时，可以调用 Anamnesis 的 `anamnesis_recall_memory` 查询长期聊天，调用 `mw_memory_lookup` 查询本插件记录，调用 `mw_profile_lookup` 查看当前会话的人物资料。需要在对应插件启用工具，并使用支持工具调用的模型；工具可用不代表模型每次都会主动调用。

### 只主动查询

若只希望在需要时取用本插件记忆，选 **不自动回忆，只在主动查询时取用**；当前生活状态与画像仍会提供给模型。`mw_memory_lookup(topic)` 可查询当前会话、共享生活组及明确全局记忆，不会因自动记忆设置为 `manual` 而失效。它按话题检索，最多返回 5 条和 6000 字符；没有命中时明确返回未找到。

设置使用顶栏的编辑范围。会话正在继承全局设置时，需要先开启“本页配置”，才能保存独立策略。共享生活组使用同一份生活配置。

## 上下文会增加多少

无法仅凭插件数量给出固定 token 数。一次请求的增量取决于两边实际召回的内容、画像和状态长度，以及模型的 tokenizer。

`memory.recall_max_chars` 限制本插件常规自动召回的完整文本行，包含日期、情绪与附带原文；超过预算的条目跳过，不截断事实，不修改数据库。默认 1200，范围 0～12000；0 表示不自动召回。自动召回还会合并同一天、同地点、相同参与者的重复文本，避免同一事实在多个作用域里重复出现。

这个预算不限制外部记忆、通讯录画像、状态、近期事件或回访内容。到期回访另受“每天最多回访几次”等配置控制；选择 `manual` 或预算为 0 时也会停用自动回访。需要核对实际请求时，请看调试页的提示词预览和请求快照。

## 当前记忆库的取舍

本插件的优势是直接知道角色独处时发生的动作、地点、事件和内心变化，并让记忆参与睡眠整理、时间衰减和回访。Anamnesis 更适合检索长期、多话题的聊天知识。两边的记录来源不同，保留两者有实际价值。

对照 Anamnesis 的实现，本插件还有这些不足：

| 方面 | 当前能力与限制 | 使用建议 |
| --- | --- | --- |
| 换说法检索 | Anamnesis 支持混合检索、图谱关联及可选重排；本插件有默认关闭的轻量语义召回与关键词兜底，尚无独立重排或完整事实图谱 | 长期聊天优先用 Anamnesis；需要时再开启本插件语义检索，见 [记忆说明](memory.md) |
| 旧记录可发现性 | 作用域内先匹配话题，再限制候选数；同时检索正文、折叠前原文和关键词。可见多人发言分别召回后共用一个预算，索引仍逐步补齐 | 需要具体往事时带话题主动查；有限候选与预算仍可能漏掉相关历史 |
| 重复记录 | 仅合并同一天、同地点、相同参与者的相同文本，忽略标点差异；不同措辞及跨插件重复仍会保留 | 默认只让一边自动召回聊天 |
| 事实变化 | 有来源快照、修订历史、新事实提取与旧记忆整理分阶段；尚无完整的事实失效时间与替代图谱，旧新结论仍可能同时召回 | 稳定资料优先维护通讯录结构化字段，对变化的事实保留日期与来源 |
| 长期保留 | 写入时有约 500 条的会话／人格容量整理，仍缺少完整的归档层与保留策略设置；查询修复不能找回已清理的数据 | 需要永久保留的内容定期导出，不把“双份保存”当作全量原始聊天备份 |
| 请求总长度 | 有本插件常规记忆段的字符预算，没有跨插件统一 token 预算和语义去重 | 分别限制两边的召回量，结合请求快照观察总长度 |

目前没有把生活记忆自动导出到 Anamnesis 的同步接口。若将来统一检索，需要保留来源、会话权限和删除语义；不能直接共享修改彼此的数据库文件。
