# 接进你的群

[文档目录](README.md) · [按主题拆开的详细说明](GUIDE.md) · [返回 README](../README.md)

> **v3 变化**：主回复、工具循环、分段 / 引用 / 语音 / 表情包的发送钩子都走 AstrBot 原生管线；
> 本插件只注入人设与处境，不再自己调模型、不再发主回复。本文里关于"接管回复 / 工具型动作"的段落属于旧版。

谁来回话、分段回复、性别称呼、群名片、管理权限、和别的插件配合。

## 分段回复的节奏

她一次说了好几句时，是一段一条消息发的（而不是挤成一坨）。为了让这个过程看起来像人在打字，
两条之间会按上一段的字数停一下再发：默认 **0.03 秒/字、单条最多 2.5 秒**，
在「全局设置 → 说话节奏」里可以改，也可以整体关掉。

同一节里还有一个 **「回复时引用她的那条消息」** 开关（默认关）：打开之后，她一次回好几条时
**第一条会引用触发她的那条消息**，群里就能看出她在回哪句（尤其是 @ 她的时候）。
引用是平台级的消息段，只有 QQ / OneBot 这类支持它的平台能用（aiocqhttp、NapCat、Lagrange）；
别的平台会自动跳过引用、照常把消息发出去，不用为了这个开关换平台。

现在是三档：**不引用 / 总是引用 / 智能**（默认智能）。智能的判断是"这一轮要回一串消息"——
她还在回上一条时又来了新的，才带引用；单独一句对答不顶引用。她发的图片同样算"第一条"。
调试回显永远不带引用。

连发合并默认关闭，避免和上层消息防抖插件重复处理。手动打开合并后，同一节里的
**「新消息打断还没回完的回复」**（默认开）才参与这一轮：她还在生成时群里又来了一条，
这一次生成作废、由新消息重新触发一次回复；因为被作废的那次不算「已经回过话」，
新那一轮仍然看得到刚才那几条——相当于上一次回复没有触发过。关掉 = 把几条并成一次请求一起回。

`{user}` 认不出人时不会把 QQ 号写进句子里（会退回「你」），日志里仍然记录了真实的目标 id。


## 被 @ 时由谁回复

「全局设置 → 基础 → 被 @ 时的回复方式」现在只剩一项：

- **接管回复**：她按自己的动作系统回应，能触发 hug / kiss / 去做饭 / 去搜索这类真实动作，
  数值也会真的变化。被 @ 的消息走到大模型那一刻就由她接管，`stop_event()` 挡掉主人格那一次回复。

以前还有一项「仅注入状态」（只喂世界认知、让主人格自己用自然语言回），v2.2.0 已经删掉了：
老配置里写了 `inject` 的会在加载时**静默改成接管回复**，不会报错、也不会让她变回主人格语气。

接管失败（没配模型、模型报错、模型没给出任何动作）时**这一条就不回了**——不会换成主人格来答，
否则用户会看到「她」突然换了个说法。失败原因写进编辑器日志页的「接管失败」条目，
后台也会打一行警告，方便分清是模型挂了还是模型没给出动作。
历史对话会通过 AstrBot 的 `contexts` 原样带给模型，所以接管不等于失忆。

**她自己在忙的时候也会回你。** 插件自己在调模型（自主决策、动作续说、记忆总结、图片转述、
工具补参）时，打的是「这一条协程」的标记，所以这段时间里进来的消息照常走接管和睡觉门禁——
不会出现"这几秒里 @ 她没反应、只有主人格随口回一句"。

**同一条会话里连发的消息会排队。** 前一条还在等她开口，后一条就先等着（最多等 25 秒，
超时就不再等、宁可她多说一句），这样第二条看得到第一条刚说了什么，不会自顾自地重复回应同一件事。


## 性别与称呼

全局设置里的「性别」（女 / 男 / 塑料袋）决定文案里的称呼：`她` / `他` / `ta`。
影响范围包括编辑器界面文字、`/mw status` 等指令输出，以及模板文案里 `{bot}` 的兜底称呼。
改完记得点右上角「保存」。


## 群名片显示什么

文案写在**它自己身上**，从上往下依次生效：

1. **动作的「执行中名片文案」**（动作编辑页里写，例如做饭动作写「做饭中」）——
   她在做这件事时显示它，「在做什么」优先于「在哪儿」；
2. **地点的「在这里时名片文案」**（地点属性里写，例如书房写「在书房」）——
   她只是待在那儿、又没在做带文案的动作时显示它；
3. 都没有就显示她原来的名片。

文案跟着动作 / 地点走，换预设时它们一起换，所以不会出现"预设里没这件动作、名片却还写着它的名字"。
老配置里那张 `状态 → 文案` / `地点 → 文案` 的全局表在升级时会被搬进对应的动作和地点，
表本身只留作兜底、不再出现在编辑器里（冷启动的「刚醒」这种没有动作对应的状态由内置默认值负责）。

改名本身还有开关、模板（`{base} | {status}`）、最大长度、改名冷却这些通用规则，在「全局设置 → 群名片同步」。


## 谁能用管理指令

`/mw` 里会改东西的那几条（重载配置、重置状态、恢复默认、改群名片、跑日程、调试命令、管理会话白名单）
需要管理员权限：

- AstrBot 自己的管理员**始终**可以（所以不会把自己锁在外面）；
- 另外可以在「全局设置 → 管理员 QQ」里再列几个人，让群里的管理员也能用这几条指令。

只读的指令（`/mw status`、`/mw memory`、`/mw recall`、`/mw help`）任何人都能用。


## 与其他插件联动

### 智能意图路由（astrbot_plugin_intent_router）

那个插件负责判断「群里的哪条消息值得主人格回复」。本插件提供只读接口
`social_snapshot(session_id)`，任何同进程的插件都能拿到她此刻的孤独感 / 心潮等状态。

intent_router 侧新增了配置项：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `link_my_world` | 开 | 是否启用联动 |
| `vw_threshold_max` | 0.75 | 孤独感 = 0 时的放行阈值（更安静） |
| `vw_threshold_min` | 0.3 | 孤独感 = 1 时的放行阈值（更愿意接话） |
| `vw_cache_seconds` | 10 | 读取状态的缓存秒数 |

效果：她在她的世界里越孤独，意图路由的放行阈值越低，越容易被叫去回消息；
她累了、无聊、不太想说话时会明显更安静。会话没加进她的世界白名单时自动沿用固定阈值。

注意插件加载顺序：intent_router 可能比本插件先加载，所以它启动时探测不到是正常的，
运行期第一次判断消息时会自动生效并打日志。

#### 她也会借它的判断（回复之前）

上面那条是「越孤独越容易被叫去回消息」的反馈。装了意图路由之后还有一件事会自动发生：
它每判一批消息，就把**整批**结论挂在重投的那个事件上（`intent_router_decision`），
本插件收到后按事件身份认领给对应的聊天记录，写进 `router_directed` / `router_to` /
`router_reason` 三个字段，并在提示词里替她点一句，例如
「（意图路由判定这句是冲你说的）」「（意图路由判定这句是冲 小明 说的）」「（意图路由判定这句不是在跟你说话）」
（路由自己给了「不确定」时就照实说「（意图路由不确定这句是不是冲你说的）」，不替它把话说死）。

价值在于**她回话之前**就知道一句没 @ 她的话是不是在问她——被合并掉、正文根本没进这一轮
请求的那几条尤其需要（它们平时只有主模型回完之后才补得上 `addressing`，而那已经是下一轮的事了）。
这几个字段和 `addressing` 各占各的，谁也不覆盖谁：明说的 @ / 引用、以及主模型自己标的结论更硬，
有它们在就不再叠路由那句。

### 其他插件

她接管回复时**不往宿主的请求里写任何东西**，所以上下文理解、图片转文字等插件写进去的内容一点没动，
宿主的 `contexts` 也原样带进接管这一轮的提示词里；工具裁剪只针对白名单会话，且可以整体关闭。

**靠回复标记工作的插件**：有一类插件要求大模型在回复末尾写一个标记（例如 `[好感度增加1]`），
它们自己在回复钩子里解析并抹掉这个标记。接管模式下是插件自己调模型、自己发送的，
这条钩子默认轮不到跑，标记就会白写。打开插件配置里的 `reply_hook_bridge`（默认开）之后，
接管的回复会先经过 AstrBot 的「LLM 响应后」和「发送前」两道钩子再发出去，
所以这类插件照常工作。

同一个开关还会把接管流程的其它几个生命周期钩子**按同样的时机补发一遍**，因为接管时
AstrBot 的管线轮不到跑：准备调模型前 → `on_waiting_llm_request`；调用 AstrBot 工具前后 →
`on_using_llm_tool` / `on_llm_tool_respond`；消息发完 → `after_message_sent`。
靠这些钩子工作的插件在接管模式下才不会漏掉一半。

### 从心迹画像迁移

本插件启动时会检查同一层 `plugin_data` 下的 `astrbot_plugin_profile_weaver`：

1. 第一次迁移会复制 `profiles.json`、审计文件与 `backups/`；之后每次启动仍会按字段更新时间
   增量合并旧插件新增的记录，避免迁移前最后几条丢失。
2. 旧 key 会按当前的“按会话隔离 / 跨会话共享”设置整理。默认按会话隔离，
   每个群聊和私聊的原有记录保持独立；只有手动关闭隔离时才会收敛成一份。
3. 通讯录左侧直接列出迁移后的联系人；称呼和备注会与详细画像里的“昵称”“备注”双向同步，
   不必在两套 UI 里重复填。
4. 确认数据完整后，在 AstrBot 插件管理里停用 `astrbot_plugin_profile_weaver`。
   不要继续让两个插件同时写不同目录。

> 4.7 起通讯录不再有独立的“画像库”主页面。当前会话作用域内的记录先归到联系人，
> 联系人详情里的“画像记录”也只展示当前会话和明确全局共享的记录；
> 批量维护入口在“数据与备份 → 高级记录管理”。
> 原插件顶层指令和三个 `profileweaver_*` LLM 工具都继续可用。

模型还可以主动使用 `mw_profile_lookup` 查询画像、关系和共同经历：不传参数查当前发送者，
也可按称呼、用户 ID 或话题查询当前会话可见的联系人。它是只读工具，保留会话隔离；
旧画像插件仍启用时，也会独立注册。参数与数据范围见[记忆与通讯录](memory.md)。

另外两个可以按需关掉的干扰点：

- **日程工具**：`mw_schedule_list` / `mw_schedule_add` / `mw_schedule_remove` 是给主人格用的。
  工具本来就多的实例，可以在插件配置里关掉「把日程工具交给主人格」，这三个工具会从工具管理器里摘掉。
- **睡觉门禁**：她睡着时默认只挡"群里没 @ 她"的消息，@ 她、私聊、指令一律放行；
  这套行为在世界配置的睡觉设置里就能改（含"完全不挡"）。

### 别人给的上下文是怎么带进她的提示词的

她接管回复时自己拼提示词、自己调模型、自己发送，所以每条通道都做了显式对接。
接管钩子的优先级取的是一个很低的数（`LLM_HOOK_PRIORITY`），**故意排在所有插件后面**：
AstrBot 按 priority 从高到低跑 `on_llm_request`，而且一旦有钩子 `stop_event()` 后面的就不再执行，
所以必须让所有"往请求里写上下文"的插件先写完，我们再一起带走。

| 通道 | 处理方式 |
| --- | --- |
| `req.system_prompt` | 进「其他插件提供的上下文」。AstrBot 注入的 `# Persona Instructions` 块按**人设原文精确**摘除（`_drop_persona_instructions`）：只有拿不到原文时才退回"摘到下一个一级标题"，而且那条退路在找不到标题时不再删到结尾——宁可人设多出现一次，也不吞紧跟其后的插件内容 |
| `req.extra_user_content_parts` | 原样带进「其他插件提供的上下文」（世界树设定、helper_tools 环境感知） |
| `req.contexts` | 原样作为 `contexts` 传给她这一轮的主模型调用（记忆插件改写过的历史同样生效） |
| `req.prompt` 尾巴上的注入 | 按 `[环境感知]` 这类标记 + 空行边界摘出来单独带，用户正文保持干净 |
| `req.image_urls` | 和这一条消息自己带的图去重后一起编号、一起交给多模态主模型 |
| `event.set_extra(...)` | 只认约定的键：意图路由的事前判定（`intent_router_decision`）、世界树的临时模型（`selected_provider`） |
| 对方先 `stop_event()` | 本插件不接管，事件按对方的处理继续 |

边界：她自己的后台行为（决定去哪、走日程、主动搭话）不经过别的插件的 `on_llm_request`，
用的是她自己提示词里的时间 / 位置 / 状态；纯语音消息目前只会标注一句"这是一段语音消息"，
内容转写依赖 AstrBot 那边配置的语音转文字能力。

### Anamnesis 长期记忆

推荐以默认注入模式配合使用，并在“记忆库 → 记忆与共存设置”选择共存方案，减少重复聊天摘要和召回。范围、预算与兼容边界见 [记忆共存说明](memory-compatibility.md)。
