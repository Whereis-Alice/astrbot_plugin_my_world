# 群聊参与与主动联系

小世界可以在没人点名时顺着群聊接一句。先按语境、关系和节奏安排观察机会，再由角色决定是否开口；每次有效判断都会保留内心活动。观察次数不是发言次数目标，直接找她聊天仍由 AstrBot 原生回复。

## 从消息到开口

1. 监听只记现场，让高优先级路由先处理。用明确的原生触发标志识别 @、唤醒词、引用及显式模型请求，不把普通监听匹配产生的 `is_wake` 当成直接对话。兼容 helper_tools 的关键词唤醒、防抖合并及显式拦截。待回登记跟随实际管线，结束或取消后释放，长回复不会因超过五分钟误放行。
2. 默认等 4 秒安静期合并连发；持续热聊最多聚合 12 秒。等待不占模型槽，同一个生活只保留一个聚合任务。
3. 不再前置随机抽签。「参与程度」的普通观察基准分别为 15、7.5、4 分钟；相关话题更早观察，真实续聊优先，最近发言按完整回合留白。一句话拆成几段只算一个回合。当前实际会话中好感高的参与者，其自身相关内容得到额外优先；不借用别处关系、不因高好感而插入无关话题。默认同一生活每小时最多 12 次新消息判断，可调整上限及关系权重。这是模型观察预算，不是发言次数目标。
4. 一次请求同时决定台词与可选引用。保留完整角色卡、心情与当前时间，从本群近十分钟消息中按话题、实际参与者与续聊选择现场，沿用上下文条数设置；只把最近 180 秒视作可直接回应的现场。引用原句可从有限留档补回完整父链，即使它已离开现场窗口，也只作为理解背景。相关时恢复旧经历、人物关系和未完约定，区分梦境、想法与实际进展；自己的生活材料按话题相关性选择，只有明确问近况时额外带入地点和当前活动，避免突然播报生活。包括自己说过的话以避免重复，不携带别处私聊、整套地图、规划和动作协议。
5. 一次请求同时返回 inner、intent、motivation、say、reply_to。自主判断始终可以旁听，旧自然沉默配置不再要求主动开口；直接对话不受影响。话题结束、纯指令、缺必要上下文或明确要求安静时不追答。安慰贴着具体失落，兴趣随相关细节表达。引用只选本群未过期的真实消息；任意平台 ID 不会被采用。生活分享与主动找人的额度继续独立校验，不能通过续聊意图绕过。
6. 思考期间有新消息、改动配置或切换人设，旧结果作废。忙碌或观察留白时只等待，不把未进模型写成旁听决定；结束后重看仍在进行的现场，过期不补答。同一生活的各会话分别保留聚合消息，按等待顺序处理。模型已判断的批次不会反复调用；成功发送才推进已回应水位。发送前及打字等待后复查权限、原生回复与时效。

简短陈述、表情和疑问也可进入观察，不因缺少检索词而被跳过；明确的简单应答与空白仍留白。若正常回复或活动在观察排队期间开始，保留尚未判断的现场，结束后再核对时效。等待不记成旁听、不占观察次数，仍由模型决定是否开口。

现场接话不使用旧版20分钟插话冷却、每日找人额度、每小时自主行动或生活文案额度，也不启动「没人理她」冷却。观察节奏随语境与关系调整，统一后台每日调用/Token 预算与并发仍有效，模型失败会退避。睡眠、低精力、不可中断的活动、工具执行与正在处理的对话优先完成；安静且可中断的个人活动可继续，不丢进度。

## 各模块怎样配合

| 入口 | 约束 |
| --- | --- |
| 新消息现场接话 | 总开关、目标白名单、参与程度、观察上限、关系权重、现场判断、后台总预算、时效与回复避让。 |
| 浏览后接话 | 额外浏览接话开关、总开关与实际来源白名单；参考本次刚留下的想法，群/私聊分别判断实际读过的未回应消息与后续变化。现场曾旁听不阻挡新阅读判断，同次阅读只判断一次；消息年龄不按 15 分钟固定截断，始终允许自主沉默，不扣找人额度。 |
| 找人、想念、亲近联系、戳一戳 | 明确授权后，共用找人节奏、每日联系额度和未回应联系人等待；同一联系短时续说只计一次。 |
| 日程与事件、问候、生活分享、普通自主动作续说 | 总开关、主动发言及生活分享两份实际目标名单；日程与事件还有各自来源开关。 |
| 直接回应 | AstrBot 原生 Agent、工具与回复；不扣主动联系额度，回应结束后其它找人模块先留白。 |

主动找人默认在最近发言后留白 90 秒；某人未回应时至少等 6 小时再联系，同一生活内同平台的群聊与私聊共用等待。不同平台同号用户分别记录，明确回应才解除等待。一次联系在 120 秒内续说只计一次，超过窗口重新计数；新增联系人仍核查其等待状态。失败不计额度或已回应水位。

旧版例行计划兼容原有插话字段，但执行时会用当前现场与同一参与协议重新考虑，不直接照发旧台词，引用也只落原会话。

## 与 OutputPro Split 配合

无需关闭 OutputPro Split 的智能引用。普通回复继续走 AstrBot / OutputPro 原有处理；后台接话使用 `Context.send_message`，直接向平台发送可选 `Reply` 加正文，不进入结果装饰钩子，不调用第三方插件内部管线。因此不会重复引用或被两套分段逻辑重复拆分。

后台接话通常只有一句；需要分段时由小世界适配器处理，引用仅放首段，不自动 @。引用编号不写入正文和角色历史。平台须支持主动消息与 Reply 组件；没有真实消息 ID 时仍可不带引用地接话。

核查基于已安装的 OutputPro Split v2.3.9：其 `ReplyStep` 遇到已有 `Reply` 会保留它。未修改其代码或配置。后台主动消息不会享有仅在 OutputPro 结果装饰阶段执行的清洗、替换等功能。

## 设置与检查

打开 **设置 → 自主发言**，应用全局白名单，选择新消息接话开关、参与程度、每小时最多观察次数及好感对观察的影响。自主决定始终可旁听；旧自然沉默配置保留兼容，不再展示强制主动发言开关。日程、事件、早晚问候在「生活的表达」；找人额度、留白与等待在 **主动找人的保护**。统一后台总预算在 **生活与作息 → 后台预算**。

观察机会不要求每条群消息都回答，也不要求每项生活活动都播报。生成失败、空结果或错误 JSON 不会被替换成固定台词；不发送，也不反复重试同一批消息。睡眠、权限、预算、现场过期与原生回复避让继续生效。控制台分开显示等待、判断中、旁听、失败及已接话，保留原有布局。

顶栏总开关暂停全部自主发言，保留安静生活与直接回应；独立配置不能扩大白名单。旧孤独阈值、最低消息数、插话冷却和判断间隔不再作为现场接话设置展示。控制台显示旁听/接话结果，模型调用页可筛选「群聊参与判断」。

`eval-run` 的 `variant: "participation"` 使用相同的任务上下文选择、沉默设置、构建和解析，对合成群聊做只读测评，不发送消息或推进状态。结果附带 `context_selection`（含 `natural_silence`），可核对材料入选原因与本次模式。失败记录为错误并隐藏地址与凭据；空台词只说明这轮没有可发送内容，不能仅凭它判断角色主动选择沉默。
