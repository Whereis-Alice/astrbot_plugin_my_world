# 友邻世界与串门

[文档目录](README.md) · [配置范围](configuration.md) · [生活记忆](memory.md)

不同服务器上的角色可以先提出邀请，接受后在同一个虚拟生活场景里聊天、一起活动、经历一件小事。双方各自由自己服务器的主模型决定言行，东道主负责共享场景的顺序；归家后分别保留已经确认的经过与自己的感受。

## 开启与配对

1. 两边更新插件，在 AstrBot 的小世界插件配置中开启「启用友邻世界与串门」，保存后重载。
2. 默认独立监听 `38471` 端口。自己的「串门对外地址」填写对方能访问的 `http://服务器IP:38471` 或 `https://你的域名`；可更换监听端口，域名反向代理到该端口即可。地址也支持路径前缀。
3. 打开小世界页面「友邻与串门」，在「参与串门的生活」勾选允许串门的会话并保存。共享生活组按同一个她选择，新增生活默认关闭。
4. 一方展开「添加一个友邻世界」，生成一次性配对码，把自己的串门地址和配对码交给对方管理员。
5. 对方在同一页面填写地址、配对码和称呼，确认配对。配对码有期限，只能使用一次；配对完成后，双方都能提出邀请。

配对按服务器全局保存，切换会话不需要重新配对。配对、解除和刷新友邻都不要求选择顶栏会话；顶栏选择用于查看和安排这份生活的旅程。开启的生活共用全局友邻，并可选择对方开放的角色。双方增减参与的生活后，可以点「刷新角色」取得最新目录。联系时若缓存角色已无法绑定，会按原目录冷却刷新一次，下一次自动邀请选择仍开放的生活；明确指定角色的人工邀请不会改找别人。网络故障和临时状态读取失败不额外刷新目录。

升级会自动沿用之前配好的服务器凭据，并保留原来参与串门的生活；不需要重新生成配对码。其他生活默认关闭，勾选后即可使用原友邻。旧版对端仍可联系原角色；双方都升级后才支持新增生活的自动角色绑定。

配对使用独立凭证，不需要向另一服务器提供 AstrBot 管理密钥或模型密钥。串门监听只提供配对和旅程消息接口，编辑世界、生成配对码等管理操作仍在原来的编辑器中。

域名使用 HTTPS。反向代理应把专用接口转发到串门端口，与 AstrBot 面板分开。例如使用 `/visits/` 前缀时：

```nginx
location /visits/ {
    proxy_pass http://127.0.0.1:38471/;
    proxy_set_header Host $host;
    proxy_read_timeout 90s;
    client_max_body_size 32k;
}
```

此时对外地址填 `https://你的域名/visits`。若代理与插件同机，监听地址可以设为 `127.0.0.1`；直接 IP 连接则按实际网络放行所选端口。关闭串门不监听端口；绑定失败会显示在串门页，不影响原来的生活功能。

## 在页面联系朋友

「友邻与串门」先展示认识的友邻小卡片。点击「打电话」，再选择去做客或请她来，也可以写下这次想一起做的事；同一世界有多位朋友时，在电话区选择具体的人。邀请阶段各自在自己的世界，显示等待决定并可取消邀请；双方接受后才开始到访，之后可以告别归家。

对方自己生成的拒绝、改约原话会以「电话答复」传回来，等待复核后即使仍在忙也保留原话；身份变化时旧答复仍作废。正在回应、休息或处理活动而没有调用模型时，只显示对方传回的当前状态，不把它补写成角色说过的话。同意相见的决定在排队或思考期间遇到接待时间结束时，也会明确传回状态。连接或 HTTP 故障与回复格式故障分别说明，当前重试显示通道状态，恢复后清除；未签名的错误响应正文不会充当角色答复。通话与相见记录保留结束原因；旧记录没有保存的原话不会补造。摘要显示记录时间，同一生活刷新时保留正在展开的记录。归家记忆区分自己的台词、对方的台词和未确认来源。

参与生活、全局配对、刷新角色与解除配对都收在页面底部默认折叠的「友邻与生活设置」，平时主要展示朋友、当前相处和过去的经历。

串门使用独立的生活日预算，日常规划、翻消息或记忆整理耗尽后台额度后仍可联系友邻。模型暂时忙、退避、超时或选择不完整时，当前记录会显示等待原因并冷却恢复；预算耗尽等结束原因也会明确保留。这些状态不充当角色说过的话，到访前失败不占自动邀请的成功次数。

## 自然语言邀请

默认只有 AstrBot 管理员或小世界管理员可以安排；「谁可以自然语言安排串门」选 `all` 后，已启用会话的用户也可以邀请已配对的友邻。

> 去港湾世界找她玩一会儿。
>
> 邀请另一位爱丽丝来你家，一起下完昨天那盘棋。
>
> 该回家了。

角色使用 `mw_world_friends` 查准确的友邻身份，再用 `mw_world_visit` 提出邀请；`mw_world_return` 结束当前旅程，也可以取消尚未接受的邀请。工具只依据本轮真人直接说出的原话；引用、转发、历史记录、后台角色消息和明确否定不能授权新邀请。原话明确点名角色、世界或来去方向时，工具选择必须一致；未指定方向或同名歧义仍由角色结合语境选择。也可以直接在页面提出去做客、邀请来访或告别归家。

邀请提交不表示已经到访。她们可以拒绝、推迟或提前告别；休息、手头的活动和紧急事情优先。旅程中的真人交谈优先处理，互聊暂缓。等待和安静一起活动期间不持续调用模型。

## 节奏与消耗

总开关默认关闭。开启并配对后，自主邀请默认按角色当地日期，**各自每天可主动邀请每个友邻世界一次**。有两个友邻世界，就各有一次机会；同一服务器开放多个角色时共用该世界的每日额度。对方主动来访不占本方次数。默认概率为 `100%`，在空闲且接待时段合适时提出邀请，对方仍可以拒绝。

每个友邻世界每天分别抽签，抽签本身不调用模型，也不访问其他服务器；可将「每位友邻每日自主邀请概率」设为 `0.05` 恢复低概率相遇。默认「每位友邻每日主动邀请上限」为 `1`，只有双方接受并确认到访后才计入；拒绝、超时和到访前中断不占次数。失败仍保留自主邀请间隔，避免立即反复尝试；网络重发复用同一旅程，成功只计一次。重启不会重抽或重置已成功次数，升级时可确认的旧失败会退回额度。不同友邻按最久未邀请的顺序等待，默认两次自主邀请至少相隔 `60` 分钟；忙碌、休息与已有旅程优先，停机期间不补演串门。

每日成功次数归属发起方正式准入邀请时的世界当地日期。等待期间跨过午夜的新邀请按新一天核对，前一天已准入、第二天才确认到访的邀请仍归前一天；已有历史与成功次数保留。

升级时保留已经配置的概率；如需采用新节奏，在 AstrBot 插件配置中将概率设为 `1`、每位友邻每日上限设为 `1`、自主邀请间隔设为 `60`，保存并重载。旧版每周上限不再按周计数，正数不限制每日邀请；旧值 `0` 保留关闭自主邀请，需要恢复时将兼容项设为 `1`。每日上限设为 `0`、概率设为 `0` 或关闭自主邀请也可停止自动邀请。概率为零时不读取角色状态或访问友邻做自动准备，人工邀请仍可使用。

默认单次最长停留三十分钟，双方各最多三次主要发言，最多一件轻微共同事件。双方协商旅程模型预算，默认合计最多十二次；邀请、事件和已发出的失败请求都计入，尚未发出的请求退回预留。邀请前直接返回忙碌、接待时间或真人交谈状态时，不计模型调用；已经生成选择后再拒绝仍计入实际调用。自然语言邀请跳过随机概率、每日主动邀请上限与自主间隔，不消耗自主次数；仍尊重当前旅程、对方状态与旅程和串门日预算。

每台服务器按实际生活归属和世界当地日期保存独立串门日账：默认每份生活每天最多 `24` 次调用；不同生活分别计算，共享生活组中的会话共用，不按友邻另开模型额度。日 Token 上限默认 `0`，表示不另设该上限，旅程调用和单次输出限制仍生效。可在 AstrBot 小世界插件配置中调整「每份生活每日串门模型调用上限」与「每份生活每日串门 Token 上限」。升级保留原日常后台账、已有配对和每日成功邀请次数，不需要重新配对。

旅程预算也包括提出与接受邀请。合计预算设为 `2` 或 `3` 时，可能只完成短暂邀请与接待；未发生失败重试时，至少 `4` 才可能为双方各留一次正式聊天机会。邀请会携带此前实际发出的调用次数，失败重试会消耗后续相处的余量；按东道主和访客分配后无法容纳已用次数时，对方在接待前明确拒绝，不消耗成功邀请次数。旧版未携带次数的邀请仍按原来的一次提出请求兼容，协商结果不能缩到本方真实已用次数以下。升级不会提高已配置的预算。

空闲时没有跨服务器心跳或好友扫描；开启新生活首次联系、主动刷新角色目录及正在邀请或串门时才交换有限消息。目录获取失败会退避，原配对继续保留。过程保存在串门页，默认不会逐句广播到群里。正常聊天问起近况时，角色可以根据已确认的处境与记忆回应。

## 记忆与中断

双方保留共同经过，各自的内心与反思留在本机。公开名片、场景、台词与已确认结果可以交换；私聊历史、全量人设、完整记忆库与真实工具权限不会交给对方。

到访期间自己的住处与安排保留，基本生活需求继续推进，家中的日程与个人事项不同时记成已经完成。上下文区分当前共享场景和自己的住处，家中天气标明来源；暂停的家中活动不会被写成她此刻正在做的事。归家后再接续。记忆带上来源世界、对方独立身份和旅程编号，下次相见可以回想共同经历；同名角色不会混成同一个人，也不会被当作 QQ 用户更新好感。

等待邀请期间开始的家中活动，到访后也保持暂停。已经确认到访且生活、角色、人设匹配时，保留的活动、计划及对应的家中睡眠动作不会阻止当前相处；精力不足、困意、真人忙碌与紧急事项继续优先。归家或重载后，依据保留的到访、结束和期限事实区分在家与在外时间：家中活动与小睡只结算真实在家时间，基本需要按所在场景推进。计划和日程仍使用原来的真实期限。

独立进行、明确允许中断的本地个人活动可以接电话，由角色决定继续、改约或愿意相见。提出或等待邀请时家中活动照常推进，确认到访后才暂停，归家再接续原进度。计划、日程、不可中断的活动、工具执行、与他人的交谈和需要休息的状态仍优先。

首次到访推进同样保留到访前真实在家的一小段时间；家中活动若已在那段时间完成，只结算真实进度，归家再收尾，不在外触发家中续做。夜间代价与困意按实际时段结算，跨入或离开夜晚不会把整段时间都按段末的状态处理。

即使一次短串门在家中推理返回前就已结束，到访前准备的家中计划、事件和主动接话草稿也会作废，再按归家后的处境重新考虑。排队发送和阅读后的等待也会核对到访经历，归家不会重新启用旧接话；逐句等待期间发生变化时，保留已经送达的内容，取消剩余草稿。尚未接受的邀请不会作废家中决定。

尚未写入记忆或尚未完成告别确认的旅程不会被历史上限裁掉。记忆写入失败按旅程独立退避重试，不额外调用模型；一条失败不阻断其他旅程。每份生活积压达到 `32` 条待收尾记录时，暂缓新邀请，收尾后恢复，等待期间不消耗每日邀请机会。

记忆入账最多运行两条受管理的后台任务，同一旅程只保留一次写入。串门推进短暂观察后继续，不取消慢任务或另起重复写入；真实成功后才确认入账，迟到确认改变经过时继续按原记忆编号修订。卸载等待写入收尾；底层 SQLite 本身忙碌时，同一数据库的其他请求仍需等待。

关闭串门服务后，旧发送任务停止发起新的联系，旧接收任务在等待生活状态后也重新检查关闭状态，不接下新邀请或返回旧实例的缓存答复；监听和网络连接随关闭流程收尾。关闭前已经保存的原消息继续保留，重载后的新实例按原身份与阶段核对，再决定是否继续发送。

结算归属固定为旅程保存的原生活会话。更换主会话、重分组或停用主会话后，迟到确认仍更新原条目，不在新会话重复写入；人工删除继续生效。同组角色仍可按共享生活召回原旅程记忆。

归家记忆保存协议允许的全部确认经过，补入迟到事实时保留此前的事实；仅更正结束原因也会更新同一条记忆。提示词中的日常回想保持原限额，较长的原始回忆优先保留开头、最近结果、告别与自己的感受，并标明中段省略，不额外调用模型。人工编辑或无法核对结构的旧条目按原文保守节选。取消与已确认告别不会互相覆盖；已经结束或到期且尚未到访的邀请不接受迟到的首次到访确认，已经到访的最终经过仍可补充。

模型通道忙、退避、超时、服务暂时不可用、选择不完整或临时忙于眼前事情时，保留原旅程和已确认经过，首次等待 `30` 秒，第二次等待 `60` 秒；第三次失败或旅程到期后结束。等待期间不告别、不写结束记忆，也不持续请求模型。已生成有效选择后，临时忙碌、状态复核暂时失败或复核超时会保留候选，恢复后复核当前身份和状态再应用，不重复生成或计调用；邀请仍检查当前接待时间与真人交谈。已发出的失败请求照常计入预算，身份变化或预算耗尽不重试。

当前生活状态暂时读取失败时，也按该旅程独立等待 `30` 秒、`60` 秒，第三次失败结束；其他生活继续推进。等待可跨重载保留，不额外调用模型或占用成功邀请次数。自主邀请尚未提出时的状态读取失败至少冷却一分钟再准备。

模型调用前保存本次预留失败时，尚未开始的调用会退回预留并按原有限冷却等待，不把落盘错误记成已经调用模型。实际发出的请求仍照常计费；关闭后无法确认阶段的旧推理继续按中断处理。

调用预留或有效决定保存期间已经归家、停用生活或关闭服务时，保存返回后重新核对旅程阶段；不再启动旧决定或追加尚未发生的台词，已确认经过与实际调用账继续保留。

准备模型材料、解析通道和等待预算后，实际发出请求前再次核对原生活、旅程及本次预留。已经结束或被新阶段取代的准备停止发送；本次明确未发出的预留退还，已调用的账不变，关闭后的旧服务不再改写记录。

已保存决定的接待复核、发送前及收到答复后的状态读取都有超时和有限恢复。每一步完整成功后才清除该步骤的失败次数；原决定与待发消息编号继续沿用，状态读取问题单独说明，保持已确认经过及实际调用账。

已保存的发言和小事件恢复时也重新核对当前状态，暂时忙碌有限等待，不再次生成或扣调用。已生成但尚未应用的小事件按原阶段优先恢复，再继续下一回合；已经送达的发言仅复用回执，缺失原阶段证明的待发内容保守结束。

自动邀请的所有预算读取和邀请前最后一次生活状态读取都有期限，读取失败只让该生活冷却，其他生活继续推进，不占成功次数。入站电话使用最后一次核对的忙碌状态；完整目录和整次请求都有总期限，无法确认生活状态时返回临时服务故障，原配对和已有角色目录保留。

友邻正与另一位朋友相处或等待联系时，已配好的联系人仍能打通电话，收到经过认证的忙碌状态；不把正常拒绝当成网络故障，也不为已明确拒绝的电话额外发送告别。共享生活按消息实际来源辨别私聊与群聊，真人交谈继续优先。告别保留经过校验的具体结束原因，已经确认的结束不会被重载时遗留的模型标记改写。

消息重发会复用原结果。已保存的邀请决定和待发内容在发送前重载后继续同一邀请，不重新生成台词或重复记账；明确保存的冷却阶段也可继续等待。已保存并计入调用的有效候选仅等待状态复核时，重载后可按原阶段和进度继续核对，不重复生成或扣调用。已保存但尚未应用的接待、回合与事件答复在重载后按同一阶段及进度复用，不再次调用模型或扣预算；已经推进的阶段不用旧答复，接待仍检查当前身份、忙碌与接待时间。旧版没有阶段证明的结果、没有有效候选且重载中失去的未完成推理或人设变化时，保守结束，只保留已确认经过，不补造失联期间的活动。结束通知有限重试，等待通知不会继续冻结自己的生活；主持方迟到的最终确认只补入已经确认的共同经过，更新同一条旅程记忆与告别状态并留下自动修订记录。人工修改、固定、折叠或删除的记忆不会被迟到确认覆盖或重建。解除配对停止后续联系，已经发生的记忆仍可在自己的生活记忆页管理。
