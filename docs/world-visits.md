# 友邻世界与串门

[文档目录](README.md) · [配置范围](configuration.md) · [生活记忆](memory.md)

不同服务器上的角色可以先提出邀请，接受后在同一个虚拟生活场景里聊天、一起活动、经历一件小事。双方各自由自己服务器的主模型决定言行，东道主负责共享场景的顺序；归家后分别保留已经确认的经过与自己的感受。

## 开启与配对

1. 两边更新插件，在 AstrBot 的小世界插件配置中开启「启用友邻世界与串门」，保存后重载。
2. 默认独立监听 `38471` 端口。自己的「串门对外地址」填写对方能访问的 `http://服务器IP:38471` 或 `https://你的域名`；可更换监听端口，域名反向代理到该端口即可。地址也支持路径前缀。
3. 打开小世界页面「友邻与串门」，在「参与串门的生活」勾选允许串门的会话并保存。共享生活组按同一个她选择，新增生活默认关闭。
4. 一方展开「添加一个友邻世界」，生成一次性配对码，把自己的串门地址和配对码交给对方管理员。
5. 对方在同一页面填写地址、配对码和称呼，确认配对。配对码有期限，只能使用一次；配对完成后，双方都能提出邀请。

配对按服务器全局保存，切换会话不需要重新配对。配对、解除和刷新友邻都不要求选择顶栏会话；顶栏选择用于查看和安排这份生活的旅程。联系对象按双方实际参与的共同会话匹配：同一个群联系对方在这个群中的生活，私聊单独匹配，共享生活组按启用的成员确认。没有唯一对应生活、对方正忙或额度不足时等待，不改找另一个群里的角色。双方增减参与的生活后，可以点「刷新角色」取得最新目录；自主串门也会限频刷新，不为匹配调用模型。网络故障和临时状态读取失败不额外刷新目录。

升级会自动沿用之前配好的服务器凭据，并保留原来参与串门的生活；不需要重新生成配对码。其他生活默认关闭，勾选后即可使用原友邻。双方都升级到支持会话匹配的版本后，才会建立新的相见；旧版对端没有归属证明时等待。已到访的旧相见沿用原联系完成收尾，历史仍属于当时实际参与的生活，不因修复挪到另一会话。

配对使用独立凭证，不需要向另一服务器提供 AstrBot 管理密钥或模型密钥。串门监听只提供配对和旅程消息接口，编辑世界、生成配对码等管理操作仍在原来的编辑器中。

域名使用 HTTPS。反向代理应把专用接口转发到串门端口，与 AstrBot 面板分开。例如使用 `/visits/` 前缀时：

```nginx
location /visits/ {
    proxy_pass http://127.0.0.1:38471/;
    proxy_set_header Host $host;
    proxy_read_timeout 90s;
    client_max_body_size 512k;
}
```

此时对外地址填 `https://你的域名/visits`。若代理与插件同机，监听地址可以设为 `127.0.0.1`；直接 IP 连接则按实际网络放行所选端口。关闭串门不监听端口；绑定失败会显示在串门页，不影响原来的生活功能。

## 在页面联系朋友

「友邻与串门」先展示认识的友邻小卡片。点击「打电话」，再选择去做客或请她来，也可以写下这次想一起做的事；同一世界有多位朋友时，在电话区选择具体的人。邀请阶段各自在自己的世界，显示等待决定并可取消邀请；双方接受后才开始到访，之后可以告别归家。

对方自己生成的拒绝、改约原话会以「电话答复」传回来，等待复核后即使仍在忙也保留原话；身份变化时旧答复仍作废。没有调用模型时，只显示经过认证的当前状态，不补写角色台词。连接、回复格式与预算等失败进入独立折叠的诊断区；「通话与相见记录」只留下实际相见的札记。旧记录没有保存的原话不会补造，归家记忆区分自己的台词、对方的台词和未确认来源。

参与生活、全局配对、刷新角色与解除配对都收在页面底部默认折叠的「友邻与生活设置」，平时主要展示朋友、当前相处和过去的经历。

相见札记的目录显示实际到访日期、地点与保存的原话摘要。展开后，人物署名和时间放在边注，台词沿固定正文列阅读；手机上署名移到正文上方。行动打算、个人感受、共同事件与已确认结果保持区别，系统到访只标为相见，不当作东道主说过的话。旧记录缺少可靠身份时会注明来源未确认。

旧札记正文在展开时载入页面，显示当前已读取的全部片刻；较早的内容仍可向前翻页，目录超过 20 篇可继续翻阅。刷新保留已展开的札记和已读取页面，切换生活后重新建立阅读状态，不混入另一生活的迟到页面。前后页之间有缺口时保留补齐入口，空页保留重试，不静默声称全部载入。正式 log 优先于旧局部 transcript。正文末尾显示真实结束状态、时间和保存的原因；旧原因没有保存时明确说明，不补造。正在进行的记录显示实际等待与下一步交接。页面只展示保留记录，不生成新的台词或补造经过。

页面以主题场景、共同地点、活动时间和路线展示当前生活，已经确认的对话留在场景中。标题、空闲状态和配置保持紧凑；未接受的邀请不画成已经到访，过去的经历也不显示仍在走动的时钟。

自主串门使用独立的生活日账，默认不设每日调用和 Token 上限；日常规划、翻消息或记忆整理耗尽后台额度后仍可联系友邻。模型暂时忙、退避、超时或选择不完整时冷却恢复；这些技术状态进入诊断，不充当角色说过的话，到访前失败不占自动邀请的成功次数。

## 自然语言邀请

已启用生活的会话中，用户可以用自然语言安排已配对的友邻。生成配对码、增删友邻等管理操作仍使用原管理权限。

> 去港湾世界找她玩一会儿。
>
> 邀请另一位爱丽丝来你家，一起下完昨天那盘棋。
>
> 该回家了。

角色使用 `mw_world_friends` 查准确的友邻身份，再用 `mw_world_visit` 提出邀请；`mw_world_return` 结束当前旅程，也可以取消尚未接受的邀请。工具只依据本轮真人直接说出的原话；引用、转发、历史记录、后台角色消息和明确否定不能授权新邀请。原话明确点名角色、世界或来去方向时，工具选择必须一致；未指定方向或同名歧义仍由角色结合语境选择。也可以直接在页面提出去做客、邀请来访或告别归家。

自然语言和页面上的真人邀请都标记为人工安排，双方整趟不占插件的每日成功次数、调用或 Token 额度，不受自动概率、间隔、接待时段与自动后台退避限制。旧存档里的非自动邀请不会被猜测成新的人工安排。邀请提交不表示已经到访；她们仍由自己的人设和真实处境决定是否愿意见面，同一角色不会同时出现在两段旅程里。旅程中的真人交谈优先处理，互聊暂缓。

再次联系当前朋友可以提出接下来的活动，静处期间的新想法也会同步给对方，等双方各自回应后再决定是否换活动。新请求不会直接改写当前地点、安静安排或共同约定的归家；已经约好归家时，先按约定结束，再独立邀请。联系另一位朋友则等待当前旅程结束后再打电话，不把她复制到两个世界。

## 一起出门与共同事件

共同活动可以自由提出和组合，没有预设玩法目录。每段相处保留当前局面、物件、未完事项与具体行动，后续决策持续参考这些事实。自己的小动作由本人选择，协作步骤等待双方独立回应；东道主依据已提交且计时结束的动作确认公开结果，双方分别形成个人感受。

合作回应对应具体邀请，避免两件不同的事情被当成一次合作。她们可以取消自己的动作、拒绝合作，再独立决定接下来做什么；取消不会变成完成。确认一个结果只结算与它相关的动作，其他未确认事项继续保留。

整段停留、具体动作、安静相伴分别计时。烧水、冲泡、倒茶和饮茶可以连续或合理并行，短动作支持秒与小数时长；换地点时给出合理路程，目的地动作到达后才开始。模型或网络延迟不拉长原动作，也不补造期间的新行为；经过计时只表示投入时间结束，发现、成功与输赢仍需结果依据。到约定归家时间后，未确认结果保持未完。

串门期间实际读到的群聊与已经发送的回复，按发生时间进入本人本地的当前经历，下一轮可影响心情、建议和行动。重要交流可以唤起一次回应，既有计时动作与归家约定继续保留。另一位通过本人选择的现场交流了解这些内容；群聊原文与私人感受不会直接成为跨服务器共享材料。活动里程碑、各自感受和本地交流短纪要进入原旅程记忆，相关话题和下一次见面可以自然接续。

重载或通知中断后，已写入的群聊纪要会恢复补进原旅程记忆，重复通知不会新增另一条记忆。记录按实际归家时间核对；页面将约定时段与实际相处时间分别展示，提前结束或途中归家不会显示为完成了原定活动。

在「友邻与生活设置 → 串门群名片状态」可选择独立状态模型、开关与长度；留空使用当前会话默认文本模型。模型根据已经确认的当前事实生成短状态，关闭模型时使用事实短文案。正在赶路、做事、等待与商量会随真实进展替换；尚未执行的下一站或未确认结果不能作为当前状态。札记优先展示短纪要、最近里程碑与未完事项，完整原话折叠保留。

双方升级后，新相见使用共同活动协议，旧旅程按原保存的协议收尾。东道主根据自己的可达地点、邻接路线和近期兴趣提出具体活动，访客独立决定是否接受。她们可以沿途散步、去公园或其他生活中的地点，一起做事、遇到小事件，也可以只安静相伴；只保存模型实际确认的地点和经过。

活动按真实时间和对话节点推进：提出、确认、相伴游玩、接着交谈、商量下一站或归家。两边共同确认地点与活动后，仍可以接着讲故事、下棋时聊天或回应对方的动作；不会把整段活动强制设成沉默。各自选择下一次接话或安静相伴多久，共同安静段内不联网、不逐分钟调用模型。到节点时再各自表达感受、决定接下来去哪；人工安排不沿用旧的三十分钟、三回合和十二次调用上限，后续确认的活动可以继续延长相处。

她们可以在活动开始时各自同意结束后归家，并提前留下自己的告别原话，到约定时间再执行。管理员另设有限日额度且暂时用完时，保留已确认地点，等当地额度恢复或配置调整后再商量；不编出「预算用完」的告别，也不在等待中继续拨模型。联络期限随共同确认的活动续期，失联仍按原恢复机制收尾。

相见记录按角色和实际节点区分台词、动作与各自经历，较长对话可展开更早内容。跨服务器消息使用有界分页并验证省略部分的前缀，双方本地保留完整经过和稳定编号；页面翻看更早记录也按需读取，不为展示调用模型。

QQ 问起「在干嘛」时，实际回复提示词读取当前已经确认的朋友、地点、活动与进度。尚未接受的下一站不会变成当前地点，时间流逝也不会自动编造发现、胜负或完成结果。自己的家中活动保留进度，归家再接续。

问起「有在跟谁玩吗」等近况时，她也能参考最近六条已记录的有效互动，分清自己与同伴的原话、各自经历和确认的事件结果。只有消息提到同伴、地点、活动、刚才经过或回复状态等相关话题时才带入这段详细记录；普通寒暄和无关问题只保留一行当前相处状态，像串门中顺手看消息一样回复。通过 QQ 回消息不表示已经离开同伴；生活中的朋友与群里谁在线分别理解。未发送的候选、动作打算与对方私密心事不进入这份聊天依据。材料只放在本轮临时上下文中，邀请尚未到访、归家后、其他生活或更换人设时不沿用；共享同一生活的群聊与私聊可以看见同一段相处。

回复后的复盘保留本轮准备时的实际场景；回复期间已经归家或进入下一段相处，仍按这条回复当时的地点记账，不把家中存档位置当作串门中的当前位置。旧内心草稿在相处期间只提供当时的心情和感受。省略主语的短追问会用嵌入模型判断是否关联这次相处；这是轻量语义检索，不调用聊天模型，嵌入不可用时只保留短状态。其余材料均读取已有事实，不预设她必须说哪一句话。

## 节奏与消耗

总开关默认关闭。开启并配对后，自主邀请默认按角色当地日期，**各自每天可主动邀请每个友邻世界一次**。有两个友邻世界，就各有一次机会；同一服务器开放多个角色时共用该世界的每日额度。对方主动来访不占本方次数。默认概率为 `100%`，主动提出邀请仍核对空闲状态和接待时段；清醒时收到邀请不因接待时段关闭而机械拒绝，由角色结合真实处境决定是否愿意见面。

每个友邻世界每天分别抽签，抽签本身不调用模型，也不访问其他服务器；可将「每位友邻每日自主邀请概率」设为 `0.05` 恢复低概率相遇。默认「每位友邻每日主动邀请上限」为 `1`，只有双方接受并确认到访后才计入；拒绝、超时和到访前中断不占次数。失败仍保留自主邀请间隔，避免立即反复尝试；网络重发复用同一旅程，成功只计一次。重启不会重抽或重置已成功次数，升级时可确认的旧失败会退回额度。不同友邻按最久未邀请的顺序等待，默认两次自主邀请至少相隔 `60` 分钟；忙碌、休息与已有旅程优先，停机期间不补演串门。

每日成功次数归属发起方正式准入邀请时的世界当地日期。等待期间跨过午夜的新邀请按新一天核对，前一天已准入、第二天才确认到访的邀请仍归前一天；已有历史与成功次数保留。

升级时保留已经配置的概率；如需采用新节奏，在 AstrBot 插件配置中将概率设为 `1`、每位友邻每日上限设为 `1`、自主邀请间隔设为 `60`，保存并重载。旧版每周上限不再按周计数，正数不限制每日邀请；旧值 `0` 保留关闭自主邀请，需要恢复时将兼容项设为 `1`。每日上限设为 `0`、概率设为 `0` 或关闭自主邀请也可停止自动邀请。概率为零时不读取角色状态或访问友邻做自动准备，人工邀请仍可使用。

自动提出邀请前先检查本方日账，再通过认证状态确认对方的自主串门状态。配置有限日额度时，本方与对方额度耗尽分别保存，到各自当地下一日或额度配置调整后恢复检查；已经明确不能相见时，不再反复生成邀请或拨电话。人工安排跳过这些自动额度判断，真实模型调用仍保留观测和费用事实。

每台服务器按实际生活归属和世界当地日期保存独立自主串门日账。每日调用上限和日 Token 上限都默认 `0`，表示不设上限；不限调用仍记录实际请求和用量，超过原来的 `24` 次也可继续相处。管理员可另设正数额度，有限调用或 Token 上限继续生效。不同生活分别计算，共享生活组中的会话共用，不按友邻另开模型额度；自动邀请仍沿用每家每日一次和默认 `60` 分钟间隔。人工安排不扣这份日账。升级保留已经配置的有限额度、原日常后台账、已有配对和每日成功邀请次数，不需要重新配对。

旧版单次时长、发言次数与旅程调用上限只用于旧协议兼容；新共同活动不按这些值强行告别。自主日账仍记录实际发出的失败请求，尚未发出的预留退回；人工整趟则跳过插件额度，保留实际调用事实。双方未协商新协议时继续按旧方式交接，不能擅自放大对方的旧预算。

空闲时没有跨服务器心跳或好友扫描；开启新生活首次联系、主动刷新角色目录及正在邀请或串门时才交换有限消息。目录获取失败会退避，原配对继续保留。过程保存在串门页，默认不会逐句广播到群里。正常聊天问起近况时，角色可以根据已确认的处境与记忆回应。

## 记忆与中断

双方保留共同经过，各自的内心与反思留在本机。公开名片、场景、台词与已确认结果可以交换；私聊历史、全量人设、完整记忆库与真实工具权限不会交给对方。

到访期间自己的住处与安排保留，基本生活需求继续推进，家中的日程与个人事项不同时记成已经完成。上下文区分当前共享场景和自己的住处，家中天气标明来源；暂停的家中活动与未完事件不会被写成她此刻正在做的事，原事件内容作为家中挂着的事保留。

真人协助消息、编辑器推进和已有事件的接续不会在串门中推进家中事件；协助消息仍交给当前场景的普通回复，归家后再接续原事件。

记忆带上来源世界、对方独立身份和旅程编号，下次相见可以回想共同经历；同名角色不会混成同一个人，也不会被当作 QQ 用户更新好感。

等待邀请期间开始的家中活动，到访后也保持暂停。已经确认到访且生活、角色、人设匹配时，保留的活动、计划及对应的家中睡眠动作不会阻止当前相处；困意、真人交谈与紧急事项继续优先，精力略低不机械拒绝。归家或重载后，依据保留的到访、结束和期限事实区分在家与在外时间：家中活动与小睡只结算真实在家时间，基本需要按所在场景推进。计划和日程仍使用原来的真实期限。

明确允许中断的本地活动，包括普通阅读、工作、个人计划与日程活动，可以接电话；没有睡眠或紧急事件等实质阻碍时优先答应朋友。原计划和进度保留，提出或等待邀请时照常推进，确认到访后才暂停，归家再接续。精力略低由角色结合处境决定，不机械拒绝。实际工具执行、不可中断活动或真人交谈暂忙时保留同一邀请等待，不把会话锁占用当成角色拒绝。主动邀请保留联系时段，清醒角色接电话不再被该时段机械拦截。

首次到访推进同样保留到访前真实在家的一小段时间；家中活动若已在那段时间完成，只结算真实进度，归家再收尾，不在外触发家中续做。夜间代价与困意按实际时段结算，跨入或离开夜晚不会把整段时间都按段末的状态处理。

即使一次短串门在家中推理返回前就已结束，到访前准备的家中计划、事件和主动接话草稿也会作废，再按归家后的处境重新考虑。排队发送和阅读后的等待也会核对到访经历，归家不会重新启用旧接话；逐句等待期间发生变化时，保留已经送达的内容，取消剩余草稿。尚未接受的邀请不会作废家中决定。

相见札记与未相见的失败诊断分别按配置的历史上限保留，失败邀请不挤掉已相见的正文。尚未写入记忆或尚未完成告别确认的旅程不会被历史上限裁掉。记忆写入失败按旅程独立退避重试，不额外调用模型；一条失败不阻断其他旅程。每份生活积压达到 `32` 条待收尾记录时，暂缓新邀请，收尾后恢复，等待期间不消耗每日邀请机会。

记忆入账最多运行两条受管理的后台任务，同一旅程只保留一次写入。串门推进短暂观察后继续，不取消慢任务或另起重复写入；真实成功后才确认入账，迟到确认改变经过时继续按原记忆编号修订。卸载等待写入收尾；底层 SQLite 本身忙碌时，同一数据库的其他请求仍需等待。

关闭串门服务后，旧发送任务停止发起新的联系，旧接收任务在等待生活状态后也重新检查关闭状态，不接下新邀请或返回旧实例的缓存答复；监听和网络连接随关闭流程收尾。关闭前已经保存的原消息继续保留，重载后的新实例按原身份与阶段核对，再决定是否继续发送。

结算归属固定为旅程保存的原生活会话。更换主会话、重分组或停用主会话后，迟到确认仍更新原条目，不在新会话重复写入；人工删除继续生效。同组角色仍可按共享生活召回原旅程记忆。

归家记忆保存协议允许的全部确认经过，补入迟到事实时保留此前的事实；仅更正结束原因也会更新同一条记忆。提示词中的日常回想保持原限额，较长的原始回忆优先保留开头、最近结果、告别与自己的感受，并标明中段省略，不额外调用模型。人工编辑或无法核对结构的旧条目按原文保守节选。取消与已确认告别不会互相覆盖；已经结束或到期且尚未到访的邀请不接受迟到的首次到访确认，已经到访的最终经过仍可补充。

模型通道暂忙、后台冷却、未发出的准备等待和有效选择后的接待复核，保留同一阶段，按 `30`、`60`、`120`、`300` 秒退避，之后每 `300` 秒核对到原旅程期限，不延长期限或反复生成候选。实际模型超时、服务错误和格式无效仍允许两次恢复，失败计数与临时等待分别保存。等待期间不告别、不写结束记忆、不重复日志，也不持续请求模型；恢复后核对当前身份和状态再应用。已发出的失败请求照常计入预算，身份变化或预算耗尽不重试。每阶段只要求用到的 JSON 字段，为短台词保留完整结构的输出空间，异常对象字段不会变成发言。

当前生活状态暂时读取失败时，也按该旅程独立等待 `30` 秒、`60` 秒，第三次失败结束；其他生活继续推进。等待可跨重载保留，不额外调用模型或占用成功邀请次数。自主邀请尚未提出时的状态读取失败至少冷却一分钟再准备。

模型调用前保存本次预留失败时，尚未开始的调用会退回预留并按原有限冷却等待，不把落盘错误记成已经调用模型。实际发出的请求仍照常计费；关闭后无法确认阶段的旧推理继续按中断处理。

调用预留或有效决定保存期间已经归家、停用生活或关闭服务时，保存返回后重新核对旅程阶段；不再启动旧决定或追加尚未发生的台词，已确认经过与实际调用账继续保留。

准备模型材料、解析通道和等待预算后，实际发出请求前再次核对原生活、旅程及本次预留。已经结束或被新阶段取代的准备停止发送；本次明确未发出的预留退还，已调用的账不变，关闭后的旧服务不再改写记录。

已保存决定的接待复核、发送前及收到答复后的状态读取都有超时和有限恢复。每一步完整成功后才清除该步骤的失败次数；原决定与待发消息编号继续沿用，状态读取问题单独说明，保持已确认经过及实际调用账。

已保存的发言和小事件恢复时也重新核对当前状态，暂时忙碌有限等待，不再次生成或扣调用。已生成但尚未应用的小事件按原阶段优先恢复，再继续下一回合；已经送达的发言仅复用回执，缺失原阶段证明的待发内容保守结束。

自动邀请的所有预算读取和邀请前最后一次生活状态读取都有期限，读取失败只让该生活冷却，其他生活继续推进，不占成功次数。入站电话使用最后一次核对的忙碌状态；完整目录和整次请求都有总期限，无法确认生活状态时返回临时服务故障，原配对和已有角色目录保留。

友邻正与另一位朋友相处或等待联系时，已配好的联系人仍能打通电话，收到经过认证的忙碌状态；不把正常拒绝当成网络故障，也不为已明确拒绝的电话额外发送告别。共享生活按消息实际来源辨别私聊与群聊，真人交谈继续优先。告别保留经过校验的具体结束原因，已经确认的结束不会被重载时遗留的模型标记改写。

消息重发会复用原结果。已保存的邀请决定和待发内容在发送前重载后继续同一邀请，不重新生成台词或重复记账；明确保存的冷却阶段也可继续等待。已保存并计入调用的有效候选仅等待状态复核时，重载后可按原阶段和进度继续核对，不重复生成或扣调用。已保存但尚未应用的接待、回合与事件答复在重载后按同一阶段及进度复用，不再次调用模型或扣预算；已经推进的阶段不用旧答复，仍检查当前身份和真实忙碌状态，接待时段只限制自主提出邀请，不机械拒绝清醒时收到的邀请。旧版没有阶段证明的结果、没有有效候选且重载中失去的未完成推理或人设变化时，保守结束，只保留已确认经过，不补造失联期间的活动。结束通知有限重试，等待通知不会继续冻结自己的生活；主持方迟到的最终确认只补入已经确认的共同经过，更新同一条旅程记忆与告别状态并留下自动修订记录。人工修改、固定、折叠或删除的记忆不会被迟到确认覆盖或重建。解除配对停止后续联系，已经发生的记忆仍可在自己的生活记忆页管理。
