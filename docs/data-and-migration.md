# 数据、备份与迁移

[文档目录](README.md) · [返回首页](../README.md)

数据默认保存在 `data/plugin_data/astrbot_plugin_my_world/`，包含世界配置、SQLite 状态库和 `profile_weaver/` 画像目录。备份时建议停止 AstrBot 后复制整个目录；运行中复制数据库应使用 SQLite 备份机制，避免遗漏 WAL 中的写入。

## 从世界插件迁移

本项目历史名称为 `astrbot_plugin_her_world`。首次启动前可设置环境变量 `MY_WORLD_MIGRATE_FROM` 指向原数据目录。已存在的目标数据不会被整份覆盖，先保留原目录备份，迁移后检查地图、会话和几位联系人。

数据库通过 SQLite 在线快照迁移，包含原库 WAL 中已提交的内容；日志侧文件不单独复制。数据库被占用或快照持续超过 15 秒会退出本次备份，无效数据库或快照失败不会安装目标数据库，原库保留。

## 从心迹画像迁移

首次启动会继承旧插件的画像、字段锁、审计与备份。核对通讯录中的会话范围和资料后，可停用旧画像插件，只保留本插件。旧插件仍启用时，本插件避免重复注入及注册同名工具，独立的 `mw_profile_lookup` 仍可用。

后续增量同步按字段变化进行。当前插件删除的字段，不会因为旧插件的未变化记录在重启时重新出现；旧插件实际修改该字段后，才作为新的增量来源。

## 更新后检查

自定义地图、动作与档位保持保留。缺少作息模式的配置采用自主作息，需要固定睡眠日程时请在设置中选择固定模式。恋爱、主人等特殊关系缺少自然形成开关时，采用关闭状态；已有正式关系不受影响。十档相处方案需要在设置中主动应用，不覆盖现有档位。

关系与好感按实际会话保存。对于过去共用人物档案的生活组，首次启动会向当时已有的成员会话复制旧档案、事实、关系历史、好感日志及当日计账，只补缺失记录，不覆盖目标已有档案。复制完成后各会话独立变化；以后新入组的会话不会重复复制主会话的动态好感。

统一起点保存在 `state.db` 的 `relationship_baseline` 表，以 QQ 号为键。升级不会自动建立统一起点或重置已有数值，只有管理员点击统一保存才更新各会话。未来首次建档才复制起点，刷新页面、重载与重启都不会重新覆盖；配置预设不包含这类人物运行数据，完整备份需要包含数据库。

若孤独或无聊已经很高，可等待生活逐步缓解，也可在控制台编辑当前数值。具体历史变化见 [更新日志](../changelog.md)，问题排查见 [常见问题](faq.md)。


生活事项、兴趣与阶段记录保存在原世界状态中；来源、批次、修订和向量缓存保存在同一份 `state.db`，没有独立向量数据库。旧打算首次读取时分配稳定 ID，旧计划按经过的 tick 时长迁移截止时刻；迁移不会重置现有关系与好感。升级前的整目录备份仍是完整回退方式。

## 生活记忆的职责迁移

首次打开旧数据库时，先用 SQLite 在线备份保存完整数据库到 `backups/before-life-journal-*.sqlite3`，校验成功后才开始事务迁移。备份失败会停止加载，不删除数据；事务中断可安全重试，已存在的备份不会覆盖。请保留它，文件可能包含旧聊天原话。

- 保留活动、事件、内心、生活事项的实际进展及手工生活记录。
- 原有梦转换为独立的梦境类型，不作为现实经历。
- 旧聊天摘要、滚动摘要、待总结批次，以及来源为聊天整理或无法确认的旧通用导入记录迁出活跃生活库，完整内容可从迁移前备份取回。
- 人物事实、详细画像、关系、好感、相处习惯、群词典和画像目录不参与迁除。旧的配置开关与会话独立配置一起清理，恢复旧配置也不会重开聊天摘要。

迁移只处理本插件的数据，不会操作 Anamnesis。备份并非向 Anamnesis 自动导入；需要迁移旧聊天资料时，应使用对方明确支持的导入方式，不能直接覆盖对方数据库。

生活记忆的导出文件带有 `memory_domain=my_world.life` 标识。导入会先检查整批类型、来源和字段，全部通过后才一次写入，保留原始日期与权重。导入以追加记录的方式进行，重复导入会增加重复条目。文件不能混入聊天摘要，旧通用导出不能直接导入生活库。完整数据库备份和生活记忆导出用途不同，建议都保留。
