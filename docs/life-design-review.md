# 生活与关系设计审视

[文档目录](README.md) · [自动生活](autonomous-life.md) · [生活事项](life-matters.md) · [Giftia 对照](giftia-comparison.md)

目标是让角色在原有人设基础上有连续的日子：知道自己在做什么、为什么想继续、什么时候该休息，经历能温和影响后续选择。基础身份、性格、价值观、口癖及原有喜恶始终优先。主动发言次数不能代表生活丰富程度，更多情绪分数也不能直接产生人格。

## 当前能力与剩余边界

| 范围 | 当前能力 | 仍需改进 |
| --- | --- | --- |
| 地图与移动 | 两层地图、路线耗时、地点和连通性检查，候选按当前启用动作筛选。 | 地点主要提供行动条件，环境长期变化与项目产物之间联系较浅。 |
| 动作与计划 | 持续动作、安静活动、真实截止时刻；独立计划 ID、世界修复与投入保存。项目与自主安排共用新工作准入，考虑关键事件、休息、续作、临近日程和精力。 | 日程、事件仍有各自执行器，尚未统一所有入口的抢占、中断和放弃。 |
| 日程与作息 | 每日安排感知已有事项；生成返回后核对人设、世界、日期与日程修改；独立睡眠评估、待睡让位、过劳兜底，休息前保存工作。 | 自动排程仍需首次开启；偏好尚未形成可解释的周节奏。 |
| 长期事项 | 动机、跨天步骤、阻碍、暂停恢复、阶段核对；世界内动作与原生 Agent 沙盒小步分开执行。缺素材可先准备，等待条件不霸占空闲，临时故障退避；返回前核对事项与角色上下文。 | 复杂成果仍需明确验收依据；文件读回只能证明可读，不能证明代码正确、测试通过或真实素材齐备。 |
| 兴趣与变化 | 活动逐拍保存投入，跨日期和时段记录；三十天未出现的倾向淡出，可手动整理，频繁中断提示拆小步。多日重复只提供温和节奏参考。 | 更细的节奏权重仍可完善；重复投入不能直接证明喜欢，也不能改写人设。 |
| 情绪与需求 | 经历影响心情、精力与需求；独处也有缓解方式，没人回复时降低打扰。 | 主要仍是规则数值，尚未形成充分可核对的“为什么最近更在意某件事”。 |
| 关系与好感 | 身份、好感、距离和权限分离；QQ 统一起点、各会话独立发展。逐轮评价与有来源的习惯分开；近期趋势仅取直接互动依据，不改变分数、身份和权限。特殊关系默认手动。 | 语义归纳仍依赖模型，提示约束不等于对所有不当习惯的语义验证。 |
| 记忆与来源 | 生活与人物资料分别整理；保留来源、日期和地点，梦不挤占真实材料。主动生活查询可选有界重排，返回前再次检查范围与人工修改；人物事实、详细画像和群词典保留。 | 尚无完整事实版本图或跨插件自动去重；聊天往事继续由 Anamnesis 管理。 |
| 事件 | 选择、后果、关键阶段与分享策略，事项给关键事件让位；区分动作进行中和已取得结果，静默与其他角色隔离。 | 事件后续与长期项目联系较松散，不能把随机经历堆成无休止的待办。 |
| 宿主与工具 | 聊天保留原生能力；独立生活使用原生 Runner、工具执行器和沙盒，保存逐轮用量、工具与产物收据。部分执行、重启或未知结果先核对。 | 第三方插件工具仍在宿主执行，需要显式信任；生活沙盒无法约束它们内部持有的其他权限。聊天中间轮次仍不完全可见。 |
| 图片与媒体 | 静态图保留缓存、并发去重和普通兜底；动态媒体、音轨、回看交 Motion Vision。保留临时标记，避免已确认媒体的二次转述，不改对方文件寿命。 | 不同插件的来源标记仍需维护兼容；无法确认的来源保留普通兜底。 |
| 后台与恢复 | 后台按顺序排队、同键去重；自动及手动整理锁外推理，只合并仍有效字段，睡眠成功次数与重试跨重启保存。保留每日预算，离线不补造工作进度。 | 部分普通决策仍在状态锁内等待模型，多角色日程仍有串行路径，全部推理锁外提交尚未完成。 |
| WebUI | 人物、关系、生活、模型调用独立页面，卡片展示、次要操作入抽屉，六主题和手机适配。 | 异步操作必须绑定发起会话，后续新增页面也需要保持同样的竞态保护。 |

## 下一步的优先顺序

1. **继续统一生活取舍。** 在共用新工作准入之上，收拢各执行器的中断、放弃和恢复规则，保存取舍原因与续作位置。
2. **细化温和的节奏经验。** 在淡化、人工整理与拆短提示之上，探索可解释的周节奏，始终服从原有人设。
3. **完善相处习惯的纠正。** 已有来源和人工覆盖，仍可增加失效依据与变更解释，不让相处总结授予身份或权限。
4. **让回忆更准确、可解释。** 在有界重排与命中依据之上完善冲突事实展示，优先减少错认人物和旧事实冒充近况。
5. **完善异常边界。** 生活执行账本已覆盖可观察的工具开始、返回与产物，后续继续校准不同沙盒的真实服务行为。逐步将剩余后台模型改为锁外推理、版本核对后提交，拆分多角色日程中的串行等待。

以上优先项指仍需继续加强的部分。当前适合逐步收拢职责，无需推翻 AstrBot 原生 Agent 或重建聊天系统。

## 怎样验收有自己的生活

- 无人聊天时能安静活动、休息、推进可执行项目，不用持续发言维持存在感。
- 同一项目跨天能接续，额度耗尽不拖住其他事项，中断不会抹掉在线投入。
- 安排、实际活动、世界内阶段结果和真实工具成果能清楚区分。
- 能解释为何做、为何暂时放下；异常恢复不补造经历。
- 统一关系起点不抹平各会话历史，共享世界不泄露私人约定。
- 模型不可用时基本生活继续，代价和失败原因可查，允许等待、受阻和没有新想法。
