# 生活与关系设计审视

[文档目录](README.md) · [生活工作区](life-workspace.md) · [自动生活](autonomous-life.md) · [Giftia 对照](giftia-comparison.md)

目标是让角色在原有人设基础上有连续的日子：知道自己在做什么、为什么想继续、什么时候该休息，经历能温和影响后续选择。基础身份、性格、价值观、口癖及原有喜恶始终优先。主动发言次数不能代表生活丰富程度，更多情绪分数也不能直接产生人格。

## 功能怎样共同工作

| 范围 | 当前行为 | 实际边界 |
| --- | --- | --- |
| 地图与活动 | 地点、路线、耗时、可用动作和条件共同决定能做什么，闲置时可安静活动。 | 地图是角色世界；文字描述不证明现实环境发生变化。 |
| 生活取舍 | 事项与自主安排共用准入；重要事件、日程和休息使用共同中断处理，先结算投入，再保留续作位置与原因。 | 明确取消、工具、指令和发言计划不会自动重放；旧地点、旧角色或过期的安静计划需要重新决定。 |
| 日程与作息 | 结合困意、精力、事件和已有安排；新建世界每天自动生成两项安排，日程可以接续同一事项，延期有独立重试时刻和上限。 | 已有配置保留原开关。手动立即执行是管理员主动干预，仍遵守事项自身条件与额度。 |
| 牵挂与后续 | 项目、念头与约定保留动机、跨天步骤、阻碍、阶段核对和历史；确有动机的事件可关联一个后续。 | 普通经历可以结束。现实用户的约定仍需实际兑现依据；事项不会为了凑进度凭空宣称完成。 |
| 生活节奏 | 不同日期的实际投入产生时段与周节奏参考，近期记录权重更高，久未出现则淡出，界面可展开依据。 | 重复投入不等于喜欢，经验不能改写核心人设，也不要求生活排满。 |
| 相处习惯 | 从直接互动依据归纳简短相处方式；旧习惯被纠正需要本批反证和原因，保留前后变化与人工维护。 | 语义判断仍依赖模型；习惯不授予关系身份、好感或权限。 |
| 人物资料与记忆 | 保留详细画像、人物事实、群词典和来源；固定事实冲突先进入候选，支持带版本校验的人工核对。记忆修订保留原因与前后内容，固定记忆不受容量自动清理。 | 私人约定进展与阅读感想只在来源会话交谈或显式查询中使用，不进入共享整理、自动回访和自主上下文。对话复盘的短期想法也保留真实来源，不充当共享自主生活的动机。聊天往事继续由 Anamnesis 管理。 |
| 人设与日历 | 生活规划、作息、复盘和相处学习读取完整基础人设；日程、每日额度、实际投入与记录标注共用世界日历。 | 简易人设仍是用户可管理的辅助摘要，不能替代主人设。跨午夜返回的生活决定需要重新判断，不清除原事项。 |
| 后台与恢复 | 明确的生活决策在模型等待时释放状态锁，基本时钟继续；返回后核对人设、日期、设置、归属和状态，多角色日程独立检查。模型失败与退避保留具体诊断原因。 | 实际工具和指令保持顺序执行，可能延后该角色后续动作；取消后不自动重放副作用。离线不补造工作成果。 |
| 宿主与媒体 | 聊天保留 AstrBot 原生 Agent、工具和电脑能力；个人生活使用文字模拟；动态媒体、音轨和回看交 Motion Vision。 | 聊天原生 Agent 的完整中间轮次仍不完全可见，无法确认的调用结果记为未知。 |
| 编辑器 | 一个生活入口，今日、牵挂、经历相互关联；完整日程和事件管理在抽屉中，保留配置范围、保存、生成与历史。 | 异步操作绑定发起会话，新增入口仍需遵守同样的保护。 |

## 怎样验收有自己的生活

- 无人聊天时能安静活动、休息、推进可执行项目，不用持续发言维持存在感。
- 同一项目跨天能接续，额度耗尽不拖住其他事项，中断不会抹掉在线投入。
- 日程接续已有事项，事件留下可选后续，三者既能关联也能独立存在。
- 安排、实际投入、世界内结果和现实兑现能够区分；失败、等待和放下都可以如实记录。
- 能解释为何做、为何暂时放下，以及节奏和相处习惯变化的依据；人工修改不会被旧模型结果覆盖。
- 统一关系起点不抹平各会话历史，共享世界不泄露私人约定。
- 模型不可用时基本生活继续，预算和失败原因可查，不靠增加工具执行器或电脑环境维持运转。

## v4.26.0 的审查与修正

这次沿地图、活动、作息、日程、事项、经历、内心、记忆、人物资料、关系、模型调用、发送与编辑器重新检查了闭环。现有机制已能支持独处时的生活，主要缺口在时间结算和“想做 / 真正发生”的边界。

- **实际时间**：按上一段正在做的活动结算数值，再切换状态。长停机的睡醒时间保留真实锚点；跨午夜日程按发生日期与星期检查。停机不补演工作或补发消息。
- **有限投入**：事项达到当天额度时保留部分进度、自然放下，次日继续。明确的零额度在每个小时都生效。
- **真实表达**：插件主动发送只记录平台接收的段落，并冻结实际来源会话。部分失败保留失败冷却；原生回复按自己的消息批次提交，工具中间发送不提前结束整轮。
- **持续运行**：新建世界自动安排少量活动；网络与配额错误不会通过丢历史、丢图片盲目重试。模型错误和片段不进入角色记忆，卸载取消旧工作和路由。
- **可读的世界**：编辑器以此刻、今日、牵挂和经历建立阅读顺序，减少视觉噪声，保留完整管理入口。启用和自动安排标记表示配置开关，不能单独证明后台运行健康。

原生 Agent 的逐段平台回执仍由 AstrBot 管理，宿主未暴露的发送失败无法由插件准确补判。世界内的活动和笔记是角色生活模拟；现实兑现依旧需要真实依据。

## v4.26.1 的实机补正

多会话实机审计发现，全局后台调用额度会同时承受每条回复后的复盘、管理员手动生成和自主生活规划。聊天量高的实例先在当天用完额度，之后自主计划全部退化为规则，内心页因此长时间不再增加记录，而旧状态仍只显示生活时钟正常。

现在，由人直接触发的聊后复盘和手动生成走交互通道，不占自主生活每日预算；原生聊天本来也不使用这条路径。自主计划额度真正耗尽时，规则仍负责作息与活动，并把已经产生的真实选择理由保存成简短内心记录，每个会话每小时最多一条，避免把每次规则判断都堆成独白。页面同时显示最近内心、今日调用数和耗尽状态，不再把“时钟在跑”等同于“模型生成正常”。

审计还发现大量旧版聊后复盘缺少来源标记，数据仍在 SQLite 中，却被隐私隔离逻辑当成无法确认来源而全部隐藏。现在只允许它们在所属世界的代表会话中显示；同一共享组的其他会话仍要求明确来源，原有记录不删除，也不会跨组暴露。

## 继续改进时优先看什么

目前不需要再合并日程、牵挂和经历的内部数据。它们分别保存时间安排、持续动机和实际经过；统一入口与共同取舍让它们衔接，强行改成一种任务反而容易丢掉休息、偶遇和自然结束的空间。

- **空闲选择的具体理由**：规则会参考当前时段的多日活动依据，以及刚投入过的活动，选择延续或换一种事情；规划同时读取近期个人经历与阶段所得，解释此刻的安排。安静规划复用原通道与预算，额外受一小时间隔和精力条件约束；没有新想法时可以留白，不补造独白。
- **阶段结果的内容**：阶段复核同时留下有已完成步骤依据的短小草稿、思路或未解问题，下一阶段接着这些内容规划。笔记明确属于世界内模拟，限制数量与字数，不能证明现实资料、文件或测试。复杂内容的质量仍取决于模型，需要继续观察跨天接续是否重复或空泛。
- **长期运行的体验**：继续观察一周内是否过于重复、遇到失败是否不断重试、休息后是否自然接续。以合成情境复现问题，再修正对应规则；不靠增加数值、工具或调用频率让她显得忙碌。

这些行为需要持续检查真实使用中的连贯性。模型质量、人设内容和活动配置仍影响表现；本地回归不能替代长期运行观察，也不等于对所有语义输出的正确性保证。
