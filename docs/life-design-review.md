# 生活与关系设计审视

[文档目录](README.md) · [生活工作区](life-workspace.md) · [自动生活](autonomous-life.md) · [Giftia 对照](giftia-comparison.md)

目标是让角色在原有人设基础上有连续的日子：知道自己在做什么、为什么想继续、什么时候该休息，经历能温和影响后续选择。基础身份、性格、价值观、口癖及原有喜恶始终优先。主动发言次数不能代表生活丰富程度，更多情绪分数也不能直接产生人格。

## 功能怎样共同工作

| 范围 | 当前行为 | 实际边界 |
| --- | --- | --- |
| 地图与活动 | 地点、路线、耗时、可用动作和条件共同决定能做什么，闲置时可安静活动。 | 地图是角色世界；文字描述不证明现实环境发生变化。 |
| 生活取舍 | 事项与自主安排共用准入；重要事件、日程和休息使用共同中断处理，先结算投入，再保留续作位置与原因。 | 明确取消、工具、指令和发言计划不会自动重放；旧地点、旧角色或过期的安静计划需要重新决定。 |
| 日程与作息 | 结合困意、精力、事件和已有安排；新建世界每天自动生成两项安排，日程可以接续同一事项，延期有独立重试时刻和上限。 | 已有配置保留原开关。手动立即执行是管理员主动干预，仍遵守事项自身条件与额度。 |
| 牵挂与后续 | 项目、念头与约定保留动机、跨天步骤、阻碍、阶段核对和历史；确有动机的事件可关联一个后续。 | 普通经历可以结束。现实用户的约定仍需实际兑现依据；事项不会为了凑进度凭空宣称完成。 |
| 生活节奏 | 不同日期的实际投入产生时段与周节奏参考，近期记录权重更高，久未出现则淡出，界面可展开依据。 | 重复投入不等于喜欢，经验不能改写核心人设，也不要求生活排满。 |
| 相处习惯 | 从直接互动依据归纳简短相处方式；旧习惯被纠正需要本批反证和原因，保留前后变化与人工维护。 | 语义判断仍依赖模型；习惯不授予关系身份、好感或权限。 |
| 人物资料与记忆 | 保留详细画像、人物事实、群词典和来源；固定事实冲突先进入候选，支持带版本校验的人工核对。记忆修订保留原因与前后内容，固定记忆不受容量自动清理。 | 私人约定进展与阅读感想只在来源会话交谈或显式查询中使用，不进入共享整理、自动回访和自主上下文。对话复盘的短期想法也保留真实来源，不充当共享自主生活的动机。聊天往事继续由 Anamnesis 管理。 |
| 人设与日历 | 生活规划、作息、复盘和相处学习读取完整基础人设；日程、每日额度、实际投入与记录标注共用世界日历。 | 简易人设仍是用户可管理的辅助摘要，不能替代主人设。跨午夜返回的生活决定需要重新判断，不清除原事项。 |
| 后台与恢复 | 明确的生活决策在模型等待时释放状态锁，基本时钟继续；返回后核对人设、日期、设置、归属和状态，多角色日程独立检查。模型失败与退避保留具体诊断原因。 | 实际工具和指令保持顺序执行，可能延后该角色后续动作；取消后不自动重放副作用。离线不补造工作成果。 |
| 宿主与媒体 | 聊天保留 AstrBot 原生 Agent、工具和电脑能力；个人生活使用文字模拟；动态媒体、音轨和回看交 Motion Vision。 | 聊天原生 Agent 的完整中间轮次仍不完全可见，无法确认的调用结果记为未知。 |
| 编辑器 | 一个生活入口，今日、牵挂、经历相互关联；完整日程和事件管理在抽屉中，保留配置范围、保存、生成与历史。 | 异步操作绑定发起会话，新增入口仍需遵守同样的保护。 |

## 怎样验收有自己的生活

- 无人聊天时能安静活动、休息、推进可执行项目，不用持续发言维持存在感。
- 同一项目跨天能接续，额度耗尽不拖住其他事项，中断不会抹掉在线投入。
- 日程接续已有事项，事件留下可选后续，三者既能关联也能独立存在。
- 安排、实际投入、世界内结果和现实兑现能够区分；失败、等待和放下都可以如实记录。
- 能解释为何做、为何暂时放下，以及节奏和相处习惯变化的依据；人工修改不会被旧模型结果覆盖。
- 统一关系起点不抹平各会话历史，共享世界不泄露私人约定。
- 模型不可用时基本生活继续，预算和失败原因可查，不靠增加工具执行器或电脑环境维持运转。

## v4.26.0 的审查与修正

这次沿地图、活动、作息、日程、事项、经历、内心、记忆、人物资料、关系、模型调用、发送与编辑器重新检查了闭环。现有机制已能支持独处时的生活，主要缺口在时间结算和“想做 / 真正发生”的边界。

- **实际时间**：按上一段正在做的活动结算数值，再切换状态。长停机的睡醒时间保留真实锚点；跨午夜日程按发生日期与星期检查。停机不补演工作或补发消息。
- **有限投入**：事项达到当天额度时保留部分进度、自然放下，次日继续。明确的零额度在每个小时都生效。
- **真实表达**：插件主动发送只记录平台接收的段落，并冻结实际来源会话。部分失败保留失败冷却；原生回复按自己的消息批次提交，工具中间发送不提前结束整轮。
- **持续运行**：新建世界自动安排少量活动；网络与配额错误不会通过丢历史、丢图片盲目重试。模型错误和片段不进入角色记忆，卸载取消旧工作和路由。
- **可读的世界**：编辑器以此刻、今日、牵挂和经历建立阅读顺序，减少视觉噪声，保留完整管理入口。启用和自动安排标记表示配置开关，不能单独证明后台运行健康。

原生 Agent 的逐段平台回执仍由 AstrBot 管理，宿主未暴露的发送失败无法由插件准确补判。世界内的活动和笔记是角色生活模拟；现实兑现依旧需要真实依据。

## v4.26.1 的实机补正

多会话实机审计发现，全局后台调用额度会同时承受每条回复后的复盘、管理员手动生成和自主生活规划。聊天量高的实例先在当天用完额度，之后自主计划全部退化为规则，内心页因此长时间不再增加记录，而旧状态仍只显示生活时钟正常。

现在，由人直接触发的聊后复盘和手动生成走交互通道，不占自主生活每日预算；原生聊天本来也不使用这条路径。自主计划额度真正耗尽时，规则仍负责作息与活动，并把已经产生的真实选择理由保存成简短内心记录，每个会话每小时最多一条，避免把每次规则判断都堆成独白。页面同时显示最近内心、今日调用数和耗尽状态，不再把“时钟在跑”等同于“模型生成正常”。

审计还发现大量旧版聊后复盘缺少来源标记，数据仍在 SQLite 中，却被隐私隔离逻辑当成无法确认来源而全部隐藏。现在只允许它们在所属世界的代表会话中显示；同一共享组的其他会话仍要求明确来源，原有记录不删除，也不会跨组暴露。

## v4.26.4 的稳定性补正

这次重点检查了会让自动生活“卡死”的异常输入。固定时长动作过去仍可能被模型给出的超大时长覆盖，模型计划的最近有效时间也没有上限；现在固定动作使用自己的配置，规划模式动作在上下限内取值，模型计划最多覆盖当前配置的有效期。非有限数值会回到安全默认，不再中断生活时钟。

实机中还有一个零精力角色因卧室路线断开，连续多轮无法入睡。新逻辑会先做有限重试，过劳时立即、普通情况连续失败后改用当前地点允许的睡眠动作，并继续记录路线问题。安静翻消息返回空感受但缺少引用序号时也会推进阅读游标，避免反复读同一段。

## v4.27.1 的连续运行审查

按 AstrBot 4.28.2 的真实接口重新检查地图与活动、作息、日程、事项、事件、内心、记忆、关系、发送、预算与编辑器。现有功能已经覆盖自主生活，主要需要修复跨模块运行时会让她“想完却做不了”的问题。

- **思考与时钟**：例行日程扫描每分钟推进检查游标，生活页也会刷新同一选择的查看时间，过去都会触发旧决定保护，导致慢请求反复作废。现在合并最新游标与查看时间，不把这些读取当成改变生活；实际日程执行、选择内容、人设与设置变化继续受保护。睡眠模型等待使用同一任务的超时上下文，能够正确释放角色锁。
- **取消与人工维护**：关停、超时与真正过期的决定分别处理，同时编辑状态也不会吞掉卸载取消。日历和日记回写前重新核对设置、人设、来源经历与会话归属。
- **日历与日记恢复**：错误输出不会伪装成成功的空年历，公共日期兜底可以继续重试；单个角色忙碌不阻止其他角色，单日日记退避也不堵住其他日期。私人约定从共享日记素材中排除。
- **连续的一天**：自动排程在已有生活信息之外读取日历与最近日记，使用既有上下文预算和开关。计划仍然是计划，文化日期不代表她已经参加，日记也不能证明现实工具结果。
- **成本与失败**：自动排程归入自主预算；手动生成仍可独立使用。慢失败的退避从返回时开始，避免模型等待已经耗尽退避时间，错误诊断同时隐藏认证信息。

验收使用针对性的并发与故障回归、完整测试集、无人陪聊的多日规则模拟，以及实例 API、实际生活时钟和日记维护检查。长期语言表现仍需结合真实人设和模型观察，不能仅凭时钟增长判断她的生活是否连贯。

本轮本地全量测试 2164 项通过、3 项跳过；服务器 Python 3.12 的作息、日历日记与新增恢复回归共 110 项通过。7 个启用角色的时钟持续推进，后台成功生成 6 份年历。实例过去日期的记录没有可核对的当前人格标识，日记补写按来源保护跳过；新生活记录继续按当前人格积累，不能把旧聊天或未确认归属的经历补成她的昨天。

## v4.33.1 的全面复核

这轮沿生活时钟、活动与中断、共享会话、睡眠、日程、事项、浏览与接话、上下文选择、人物关系、记忆、预算、持久化及宿主生命周期检查功能之间的交接。现有结构能够支持独处生活与自然参与，新增问题主要在后台任务准入和观察读取的副作用。

- **后台公平性**：实际有七类角色任务（决策、接话、浏览、记忆整理、自主事项种子、事项推进、社交学习）和四个全局任务。旧容量仅按六类角色任务和三个全局任务预留；20 个角色的 144 项同时排队时会拒绝 21 项。现在完整接纳这些已去重任务，仍按原并发依次运行，不增加模型调用额度。
- **观察不打断思考**：生活页和条件检查曾把“当前可以做什么”写回已经保存的生活决定；模型等待期间的页面读取可能因此触发旧结果保护。现在取舍计算只返回结果，实际自主决策采用时才保存。当前动作、日程、人设、人工编辑和关键状态变化继续受原有过期保护，不靠忽略变化来强行应用旧决定。
- **实例核对**：审查时七个启用角色的生活时钟均有近期更新，过去六小时内浏览、作息、生活规划、复盘和整理均有成功模型调用。停用会话不参与这一健康判断；没有向群聊或私聊发送测试消息。正在睡眠的角色仍按实际睡眠时长结束，精力满不等于睡眠已经完成。

完整基线验证为 2303 项通过、3 项跳过、112 个子场景通过。修复后的生活 API、后台队列、连续生活和聊天浏览定向回归在 Python 3.14 与 Python 3.12 均为 99 项及 13 个子场景通过；ruff 与差异检查通过。当前补丁不增加设置，不改变角色人设、既有生活分享授权或平台发送行为。

语言表现仍是主要的长期验收项：关注跨天事项是否重复、生活背景是否只在相关时进入交谈、安慰是否回应具体情境。优先用真实问题复现后收紧上下文与状态衔接，不用增加情绪数值、固定发言或强制排满日程来制造存在感。

## 继续改进时优先看什么

目前不需要再合并日程、牵挂和经历的内部数据。它们分别保存时间安排、持续动机和实际经过；统一入口与共同取舍让它们衔接，强行改成一种任务反而容易丢掉休息、偶遇和自然结束的空间。

- **空闲选择的具体理由**：规则会参考当前时段的多日活动依据，以及刚投入过的活动，选择延续或换一种事情；规划同时读取近期个人经历与阶段所得，解释此刻的安排。安静规划复用原通道与预算，额外受一小时间隔和精力条件约束；没有新想法时可以留白，不补造独白。
- **阶段结果的内容**：阶段复核同时留下有已完成步骤依据的短小草稿、思路或未解问题，下一阶段接着这些内容规划。笔记明确属于世界内模拟，限制数量与字数，不能证明现实资料、文件或测试。复杂内容的质量仍取决于模型，需要继续观察跨天接续是否重复或空泛。
- **长期运行的体验**：继续观察一周内是否过于重复、遇到失败是否不断重试、休息后是否自然接续。以合成情境复现问题，再修正对应规则；不靠增加数值、工具或调用频率让她显得忙碌。

这些行为需要持续检查真实使用中的连贯性。模型质量、人设内容和活动配置仍影响表现；本地回归不能替代长期运行观察，也不等于对所有语义输出的正确性保证。

## 待办状态与接续方向（v4.34.0）

此前提到的空闲选择理由、阶段笔记、任务相关的上下文选择，以及中断时保留实际投入和恢复位置，均已有实现；剩下的是验证质量并补足具体断点，不能把它们重新列成尚未开发的功能。

本轮补上了三个具体断点：

1. **中途内容与复核交接**：书签保留实际投入、思路、未解点和继续位置；复用原有低频作息调用整理，不增加逐拍模型请求。计时结束而尚未复核时，最后的思路继续进入上下文，不把步骤结束变成问题已经解决。已复核阶段不再重带旧书签，计划的标点变体不能覆盖已有思路。
2. **旧记录与最新状态关联**：有明确事项关联的旧记忆必须连同最新状态、结果和人工调整一起选择；预算不足则一同省略。阶段正文及其限定保留在概要中，标题只作活动概述。匹配使用源内容，忽略展示标签和中文虚词组合；外部插件召回块不作为新的检索线索。先过滤人设与实际对象，再评分和记录选择原因。自主规划不再末尾追加一份丢失限定的旧版摘要。
3. **可重复的跨天验证**：同一项目按七天注入时钟，调用真实模型，检查每日投入、重载、休息和阶段复核，并人工阅读相关追问、无关话题与安慰回应。初轮实际暴露了无关书签误匹配、待复核时思路丢失、标题掩盖正文限定和计划复述覆盖书签，已据此补回归。时钟注入不等于真实在线运行七天，模型语言仍需持续观察，不能只凭请求成功或计时测试声称语义全部正确。

剩余工作是长期观察：真实人设和实际群聊中是否重复、是否把尝试说成成果、安慰是否接住具体落差，以及活动与休息是否自然衔接。预览和隔离测评使用纯读取路径，不为了检查界面或生成提示词而改写表达状态。没有通过增加发言额度、硬限制或更多设置来代替这些改进。

本轮真实模型验收使用 `openai/gpt-oss-120b`：七天时钟情境共 19 次调用，随后针对无新资料的书签保持做了 3 次断点抽测，均使用合成内容和禁止发送的消息桩。进展追问保留了未确认关系，无关话题没有携带项目书签；移除提示中的笔记占位示例后，三次抽测都保留原有具体笔记。仍观察到阶段标题偶有夸大，虽然正文和最终回应保留了限定，因此不能声称所有模型输出都已解决。上述是时钟模拟及抽样，不能当成真实在线七天或长期质量保证。

自然沉默已独立为接话设置，默认关闭；新消息与浏览后接话共用。它不要求生活活动播报，也不改变生活分享白名单。与上述连续性增强分别管理，避免把“持续生活”变成“持续找话说”。

## v4.34.1 的生活、表达与界面复核

继续检查自主生活、作息、日程、事项、阶段结果、聊天参与、内心、关系与记忆、持久化、宿主接口及页面请求之间的交接。现有机制已能支持持续生活；本次修复集中在新念头失去旧项目背景、慢失败消耗退避、情绪指令过度推动亲昵，以及页面切换被旧请求覆盖。

- **有来由的新念头**：每日种子读取个人事项的动机、状态、下一步、结果与阻碍。未结束事项完整保留，已结束记录按最近时间选取，不让大量历史挤掉暂停或等待的目标。近期完成的目标不从头建项，暂停或等待的项目由原事项继续；换种说法、细化下一步和比较方法仍属于原项目。没有新方向可以留白，不要求每天新增。程序拦截忽略标点与大小写的同文目标，语义相近的目标仍由模型判断，避免自动合并意思不同的事情。
- **失败后真正休息**：种子和项目规划的失败退避从请求返回时开始，慢模型等待不再耗尽退避。非有限步骤数值被跳过，不让后台因整数转换溢出而中断。
- **表达服从情境**：情绪与亲近倾向是内部参考，基础人设、已确认关系及眼前的话优先。她可以收敛兴奋去回应具体损失，也可以尊重对方想独处；不要求每轮表演所有情绪、增加肢体动作或索求接触。数值本身不授予新关系或权限。
- **控制台保留原布局**：卡片位置、顺序和网格不变。六主题的指标卡降低色块饱和度，使用一致的文字与边缘材质，略提高小字可读性。日志与趋势回写绑定发起会话、区间及请求序号；清空后重选不会卡住，轮询也不覆盖正在输入的群名片。
- **数据库迁移有完整快照**：使用 SQLite 在线备份带入已提交 WAL，显式关闭连接后发布文件。无效、被锁或超时的数据库不发布；先迁移状态库，失败时不安装会阻止下次重试的世界配置。宿主注册版本与 metadata 同步为 v4.34.1。

## v4.34.2 的结束与暂停表达复核

这轮沿进展追问继续检查生活记录如何进入原生聊天、后台接话和自主动机。已完成或放下的事项仍可能携带旧下一步、待复核标记及阶段后续，通用指导又要求回答“正在核对什么”，导致结束的事被说成还在做。现在这几条路径都读取最新事项状态：完成时说已记录结果，放下时承认不再继续，旧待办不重新进入当前活动；阶段正文及其未确认限定仍保留，结束不会把疑问自动变成发现。

暂停与结束分别处理。暂停的事项保留中途书签、待复核的最后思路及具体阶段接续位置，并标明目前未执行。审查中又复现了阶段后续比事项下一步更具体时被一起省略的问题，已补齐；恢复前既不会假装正在做，也不会失去原有思路。这些读取没有修改事项状态、进度或书签。私人约定和其他人设仍按原有来源隔离。本轮没有修改前端代码或控制台布局。

真实模型使用 `openai/gpt-oss-120b`，全程合成角色、隔离临时数据库与禁止发送的消息桩。初轮 7 次调用复查旧表达；修正后两轮共 14 次调用，最终代码再抽测 7 次，覆盖完成结果、完成后新方向、暂停、放下、具体安慰、无关咖喱话题及独处请求。最终故事回应为“读完了，莉娜回了小镇，诺亚留在了港口”；纸飞机回应仍明确暂停与明天的打算，无关话题的选择日志没有生活事项。安慰回应一周画作丢失的具体投入，高亲近倾向下接受独处。仍可见“祝你安静愉快”等模板句，这组抽样不等于长期自然表达或全部模型语义问题已解决。

最终代码本地与服务器 Python 3.12 的扩展回归均为 646 项通过、60 个子场景通过，覆盖上下文连续性、事项推进、中途书签、聊天注入、后台接话、作息复核、日历日记及多日生活。该结果是定向扩展验证，没有代称本轮全量测试通过；ruff 与差异检查通过。服务器验证在独立临时目录中运行，测试结束后清理。实例只读健康采样间隔 66 秒，七个启用角色的时钟均推进，SQLite 检查通过，过去一小时未发现归属于本插件的错误日志；线上安装仍为 v4.34.0。实例源码、配置和生活数据未部署或修改，没有向实际群聊或私聊发送测试消息。

## v4.34.3 的等待与恢复复核

这轮检查中断、重载和等待期间的连续性。动作计时可能因为固定动作时长大于项目小步时长而继续占位；如果小步已计满投入，随后被暂停或重载，它仍可能保留为 pending。恢复过去遇到零剩余时间就直接返回，无法登记结束或进入复核。现在恢复登记保存的世界内投入，不重新执行动作、不增加实践次数，并保留原投入时间和最后未解思路；普通项目仍须复核，私人约定仍等待兑现依据。恢复仅适用于安静的世界内活动，外部操作、发言和已更换目标的旧步骤不从计时推断完成。

等待、受阻和暂停均保留当前没有执行的接续位置。等待和受阻仍是未结束的项目，可以在条件允许时继续，但聊天背景、自主动机及旧阶段记录不会把未来步骤说成手上正在做。待复核材料同时区分“做过比较活动”和“某项资料已核实”，具体发现只依据书签及阶段正文。本轮没有修改前端代码或控制台布局。
