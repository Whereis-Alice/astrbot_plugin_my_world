# 模型设置

[文档目录](README.md) · [返回首页](../README.md) · [模型调用与用量](model-calls.md)

每个文本模型槽位独立选择：**配置了就使用指定的 Provider，留空就使用 AstrBot 当前会话默认模型**。生活规划、工具整理等槽位互不继承。正常聊天继续使用 AstrBot 原生 Agent，My World 向请求补充角色处境、生活回忆与人物资料，工具循环和回复发送由 AstrBot 处理。

## 每个模型负责什么

在 AstrBot 的插件配置中选择 Provider。所有模型都应先在 AstrBot 中配置并确认可用。

| 配置项 | 用途 | 留空时 |
| --- | --- | --- |
| 说话模型 `speech_provider_id` | 正常聊天回复、主动接话与串门台词 | AstrBot 当前会话默认模型 |
| 生活规划模型（安静生活）`llm_provider_id` | 独处时的生活决策、计划与简短心里话 | AstrBot 当前会话默认模型 |
| 工具整理模型（可选）`helper_provider_id` | 整理工具、搜索和天气结果，以及图片与话题的文字关系 | AstrBot 当前会话默认模型 |
| 轻量判断模型（可选）`judge_provider_id` | 挑选、打分、工具参数补全与回合复盘 | AstrBot 当前会话默认模型 |
| 世界内容生成模型（可选）`creator_provider_id` | 生成区域、地点、动作、日程、事件草稿、日历与日记 | AstrBot 当前会话默认模型 |
| 事件结算模型（可选）`event_provider_id` | 整理事件结果及情绪、能力变化 | AstrBot 当前会话默认模型 |
| 记忆整理模型（可选）`consolidate_provider_id` | 分别归纳人物资料、生活经历与梦境 | AstrBot 当前会话默认模型 |
| 图片转述模型（可选，多模态）`vision_provider_id` | 将群友图片和工具图片预先转述成文字 | 保留 AstrBot 原生图片处理，不额外预转述 |
| 生活记忆嵌入模型 `embedding_provider_id` | 可选的生活经历语义检索；复用 AstrBot 已配置的嵌入 Provider | 由编辑器单独选择；没有可用模型时使用关键词 |

后台专用模型都是可选项，可以全部留空。指定的模型不可用时，本轮按相应任务的失败处理或预设规则继续，不会偷偷换用插件其他槽位的模型。插件不会从 Provider 列表中随意选择一个。

记忆整理的两条路径分别调用：聊天原话用于人物事实、关系和速写；已记录的生活用于合并重复、提炼要点或联想梦境。两项有独立开关，共用睡眠整理时机，不把聊天总结进生活库。详细画像的字段维护与自动提取仍然保留。

「内心活动」记录可以收录生活规划时的简短心里话、说话时一并产生的心里话以及规则选择的说明。因此，这个列表不只来自生活规划模型，也不代表模型完整的隐藏推理过程。

图片和嵌入属于不同能力。图片转述留空时，实际回复模型需支持图片输入，或由 AstrBot 配置图片转述；每次最多带几张图片可在编辑器的上下文设置中调整。嵌入模型在记忆设置中单独选择，没有可用嵌入时使用关键词检索，不会把文本默认模型当作嵌入模型。

## 怎样选择

先保证 AstrBot 当前会话的模型能稳定演绎原有人设。说话模型可以留空沿用它，也可以指定另一个模型。后台任务通常更适合响应快、能按要求输出 JSON 的模型，记忆整理需要可靠的理解与归纳能力。

例如，AstrBot 会话使用模型 A，说话模型留空、生活规划选择模型 B：正常回复、主动接话和串门台词使用 A，安静生活的规划使用 B；其他留空的文本槽位也使用 A。如果希望工具整理、轻量判断、世界内容生成、事件结算和记忆整理都使用 B，需要分别选择 B。已有配置键保持兼容，设置向导会显示各槽位及其默认规则。

说话时的判断与台词仍在同一次请求中完成，不固定拆成“后台想一次、说话再调一次”。包含台词的主动决策使用说话模型，纯静默任务使用生活规划模型；串门中的邀请、应答与对话使用说话模型，场景结算和私下回顾使用生活规划模型。显式设置说话模型后，会覆盖更早的模型路由钩子为该条消息选择的 Provider；留空则保留宿主及其他插件的路由。

推理模型可以使用，但额外思考可能增加延迟和开销。根据模型实际表现选择，避免仅为了极短的判断启用很长的推理输出。

插件默认不覆盖 Provider 的采样配置。需要时可开启插件的采样设置，调整温度、top_p 和重复惩罚；这些设置作用于插件自己发起的调用，正常聊天仍由 AstrBot 的会话配置控制。

## 查看调用与控制开销

编辑器的 **模型调用** 页面会记录触发原因、模型通道、结果及服务返回的 Token 用量。没有返回用量时显示未知，不按字符数假装精确计费。

后台规划、回合复盘、生活事项和整理可受每日预算约束；达到相应额度后，基本活动与作息继续按规则运行，需模型完成的丰富内容会暂缓。聊天模型、图片处理、嵌入与其他插件的调用各有自己的开销范围，详见 [模型调用与用量](model-calls.md)。

生活记忆可按需开启语义召回。在 **设置 → 记忆与资料 → 生活记忆** 选择 AstrBot 嵌入模型，也可使用自定义兼容接口，见 [可选语义召回](memory.md#可选语义召回)。它不改变人物资料与 Anamnesis 的职责。
