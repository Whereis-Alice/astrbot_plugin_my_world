# 模型设置

[文档目录](README.md) · [返回首页](../README.md) · [模型调用与用量](model-calls.md)

正常聊天使用 AstrBot 会话所选的模型和原生 Agent。My World 向请求补充角色处境、生活回忆与人物资料，工具循环和回复发送由 AstrBot 处理。插件模型用于后台生活和内容生成，可单独选用。

## 每个模型负责什么

在 AstrBot 的插件配置中选择 Provider。所有模型都应先在 AstrBot 中配置并确认可用。

| 配置项 | 用途 | 留空时 |
| --- | --- | --- |
| 插件用主模型 `llm_provider_id` | 自主决策、主动说话、活动续说，以及其他插件模型的兜底 | 使用会话当前 Provider |
| 打杂模型 `helper_provider_id` | 补工具参数、判断图片与话题的关系、整理天气等结果 | 使用插件用主模型，再回落到会话 Provider |
| 看图模型 `vision_provider_id` | 图片转述，包括群友图片和工具返回的图片 | 不做预先转述，由支持图片输入的主模型直接看图 |
| 判断模型 `judge_provider_id` | 挑选、打分、回合复盘及轻量判断 | 跟随打杂模型 |
| 内容生成模型 `creator_provider_id` | 区域、地点、动作、日程与事件草稿生成 | 使用插件用主模型，再回落到会话 Provider |
| 事件模型 `event_provider_id` | 生成事件结果及相应变化 | 跟随打杂模型 |
| 睡眠整理模型 `consolidate_provider_id` | 分别整理人物资料与生活经历 | 跟随打杂模型 |

睡眠整理的两条路径分别调用：聊天原话用于人物事实、关系和速写；已记录的生活用于合并重复、提炼要点或联想梦境。两项有独立开关，共用睡眠整理时机，不把聊天总结进生活库。详细画像的字段维护与自动提取仍然保留。

未配置图片转述时，主模型需要支持图片输入。每次最多带几张图片可在编辑器的上下文设置中调整。

## 怎样选择

先保证 AstrBot 的聊天模型能稳定演绎原有人设。后台任务通常更适合响应快、能按要求输出 JSON 的模型；判断与打杂可选较轻的模型，事件和内容生成可按文笔需求单独配置。睡眠整理需要可靠的理解与归纳能力。

推理模型可以使用，但额外思考可能增加延迟和开销。根据模型实际表现选择，避免仅为了极短的判断启用很长的推理输出。

插件默认不覆盖 Provider 的采样配置。需要时可开启插件的采样设置，调整温度、top_p 和重复惩罚；这些设置作用于插件自己发起的调用，正常聊天仍由 AstrBot 的会话配置控制。

## 查看调用与控制开销

编辑器的 **模型调用** 页面会记录触发原因、模型通道、结果及服务返回的 Token 用量。没有返回用量时显示未知，不按字符数假装精确计费。

后台规划、回合复盘、生活事项和整理可受每日预算约束；达到相应额度后，基本活动与作息继续按规则运行，需模型完成的丰富内容会暂缓。聊天模型、图片处理、嵌入与其他插件的调用各有自己的开销范围，详见 [模型调用与用量](model-calls.md)。

生活记忆可按需开启嵌入服务，使用独立的端点、模型和环境变量配置，见 [可选语义召回](memory.md#可选语义召回)。它不改变人物资料与 Anamnesis 的职责。
