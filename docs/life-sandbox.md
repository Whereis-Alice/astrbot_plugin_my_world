# 生活沙盒

[文档目录](README.md) · [生活事项](life-matters.md) · [返回首页](../README.md)

生活沙盒让她在独处时实际编写代码、运行测试、查阅资料和留下文件。执行使用 **AstrBot 原生 Agent、原生工具执行器和电脑工具**，My World 负责安排小步、检查生活条件和保存依据。

QQ 聊天仍使用 AstrBot 当前的电脑环境、工具与权限。生活事项使用自己的会话和沙盒：不同项目、人设和生活归属分开；同一个项目以后继续时沿用自己的环境。切换沙盒服务配置会创建新的环境，旧文件不会自动迁入。

共享生活组固定从主会话读取 AstrBot 的沙盒服务、人设工具范围与插件启用列表，不会因哪个群触发了生活推进而临时借用那个群的能力。生活页的工具清单也使用这一范围；各群正常聊天仍按各自配置运行。

## 怎样配置

1. 在 **AstrBot 电脑能力设置** 中配置原生沙盒服务。即使 QQ 电脑模式选择了本地执行，生活也只使用独立沙盒。
2. 打开 **生活事项 → ··· → 节奏与预算**，开启生活沙盒，选择沿用服务或指定沙盒类型。
3. 查看工具清单。原生沙盒电脑工具自动接入；其他工具按需单独授权。
4. 应用后点击顶栏 **保存**。卡片会说明下一步、等待条件和真实结果，点击可查看执行记录。

支持 AstrBot 原生的 Shipyard、Shipyard Neo、BoxLite 和 CUA 沙盒。BoxLite 需要运行 AstrBot 的环境已经安装并支持它，不会由插件自动安装。服务地址、访问密钥和电脑镜像继续由 AstrBot 管理，My World 页面不复制这些密钥。

“环境已配置”表示配置条件满足，真正执行时还会检查连接。服务无法连接、依赖未安装或额度用尽时，会保留事项并等待或退避重试。**不会回退到服务器本地 Shell。**

## 工具能用到哪里

| 能力 | 自主生活中的范围 |
| --- | --- |
| 原生 Shell、Python、文件读写与搜索 | 独立项目沙盒。 |
| 原生浏览器或电脑界面操作 | 沙盒类型支持时，连接该项目的独立电脑。 |
| 已启用的插件与 MCP 工具 | 展示在清单里，逐项信任后才能自动调用；仍受人设与会话的工具范围限制。 |
| 原生本地电脑、宿主上传下载、QQ 发送、后台转交与子代理工具 | 不接入自主生活执行。 |

**其他插件工具不会自动进入沙盒。** 它们可能直接读取服务器文件、调用外部账号或发送消息。勾选信任表示接受该工具已有的宿主权限；My World 无法约束工具内部另行持有的 Context、文件接口或网络连接。不了解行为的工具请保持关闭。工具定义或来源发生变化后，需要重新授权。

原生沙盒也依赖服务本身的隔离配置：不要给生活电脑挂载服务器业务目录、Docker 管理接口或注入无关账号凭据。仅仅把工作目录换成另一个文件夹不构成隔离。需要让任意第三方插件都获得硬隔离时，应在独立容器/虚拟机运行另一套 AstrBot，这超出了单个插件内工具授权的边界。

生活事件没有真实群友或管理员身份，也不借用最后一条 QQ 消息。原生电脑的服务授权只对生活沙盒上下文生效，不放宽聊天里的管理员要求。兼容性依赖真实 QQ 事件的插件工具可能仍无法在生活环境使用，此时会留下失败记录。

## 文件与真实素材

文件放在项目沙盒的 `my_world/事项ID/` 中。生活页展示模型报告且已由沙盒文件接口读回的文本产物。底层记录同时保存检查时刻和预览哈希，可通过生活页 API 查询。读回最多一百行，**只证明当时能读取，不代表代码正确、测试通过、文件永久保存或真实素材已经齐备**。工具结果另有摘要与完整返回文本的哈希。

例如，“归类并校验动漫截图与资源元数据”可以分两段：

1. 先写校验脚本，用明确标注为 `synthetic` 的小样例测试路径、字段与异常处理。
2. 等真实素材被明确提供到该项目沙盒，再检查实际文件、运行校验并留下报告。

没有提供真实素材目录，就不能声称已经扫描或整理了服务器资源。My World 不会自行搜索服务器其他目录，也没有自动把服务器文件搬进沙盒的通道。真实素材可以通过沙盒服务的受控导入功能提供；提供后在事项里写明沙盒路径，再点击继续。

沙盒可能过期或重建。历史收据仍保留，但不能当作当前文件仍存在的证明；后续 Agent 应先检查再续作。页面不自动导出到服务器或发送 QQ，避免把生成和发送混成一项可重放操作。

## 暂停、失败与核对

每轮开始前、每个模型请求和工具调用前，都会重新检查事项版本、人设、配置、工具授权、精力、作息、重要事件与临近日程。暂停不会撤销已经发出的远端操作；Shell 在超时后也可能仍运行。

- 没有开始工具的临时错误：退避后可以重新尝试。
- 工具已成功，后续模型失败：保留成果，先核对后续，避免把整个步骤重新跑一遍。
- 工具已成功，但当前小步只返回等待或受阻：同样先核对已做部分，再规划后续；正常返回也不能证明可以安全重跑。
- 工具报错也可能已经写入部分文件。只要开始过工具而未确认小步完成，就先核对，不根据失败状态自动重放。
- 工具开始但没有明确返回、重启前未结算：显示“等待核对执行”。普通“继续”不会解除防重保护。
- 核对沙盒后，点击 **核对后继续**，填写实际情况，再重新安排余下小步。已有步骤、工具记录和产物历史都保留。

模型调用页会逐轮记录生活 Agent 的原因和用量。未报告 token 时仍显示未知，并保留保守预算占位，不会以零消耗代替未知。预算、最大轮数和超时可在生活页设置；正常 QQ 聊天不使用这套生活执行预算。
