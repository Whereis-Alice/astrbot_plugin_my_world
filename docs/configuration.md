# 全局与会话配置

[文档目录](README.md) · [返回 README](../README.md)

通用配置默认由所有会话继承；需要差异时，再为某个会话启用独立配置。

## 设置在哪里

| 分类 | 内容 |
| --- | --- |
| 基础 | 人设、世界规则、初始状态与群名片 |
| 生活与作息 | 生活事项、睡眠、状态变化、能力与后台模型预算 |
| 自主发言 | 全局总开关、会话白名单、参与方式、问候、找人、联系额度与高级保护 |
| 聊天与表达 | 说话节奏、上下文与图片转述 |
| 世界与事件 | 事件、地点、天气与干涉规则 |
| 记忆与资料 | 生活记忆、日历/日记、嵌入模型、候选重排与人物资料 |
| 调试与安全 | 调试回显与内容边界 |

生活页的“节奏与预算”只调整生活事项与后台开销。记忆检索在 **记忆与资料** 中设置，也可从生活记忆页的 **回忆设置** 打开。**生活日历与日记** 同属这一分类，可为现实、同人或原创世界设置地区与文化依据，并单独控制是否把日历和最近日记作为动态上下文注入聊天。各入口修改同一份配置，应用后点顶栏 **保存** 生效。

## 自主发言的全局授权

编辑器顶部的「全局自主发言」开关立即生效，不需要再点保存。

在 **设置 → 自主发言 → 可以主动说话的地方** 勾选会话，再点 **应用全局白名单**，授权立即生效。v4.30 起默认白名单为空，已有世界也需要明确选择允许主动发言的群或私聊。登记会话用于运行生活，不等于主动发言授权；共享生活组内每个实际发送目标分别核验。独立配置、日程目标和模型指定的 `send_to` 都不能扩大这份全局名单。

v4.33 增加同一区域的 **生活分享** 授权，升级后默认不授权。只有同时命中“主动发言”和“生活分享”的实际群或私聊，才可主动讲活动进展、成果、早晚安、日程与事件；后两者还需各自开关。普通自主生活动作完成后的续说也属于生活分享，不能用日程/事件开关代替这项授权。活动、效果和记忆照常进行，被问到时仍可正常回答。只想自然接话和找人时，将生活分享名单留空；希望只与你私聊分享时，先登记该私聊，再只为它勾选两项权限。保存旧配置或独立配置不能覆盖两份已应用的全局名单。

| 关闭后 | 行为 |
| --- | --- |
| 自主找人、插话、想念时搭话、自主动作续说 | 暂停；尚未发送的自主发言也会被拦住 |
| 日程提醒、日程动作链及其后续发言 | 不向外发言，安静动作继续执行 |
| 事件求助、事件进展和结果 | 不向外发言，事件推进与记录保留 |
| 被 @ 或正常收到消息后的回复 | 保留，继续遵循原有唤醒与会话规则 |
| 移动、休息、内部动作、情绪、记忆与心思 | 继续运行 |
| AstrBot 原生工具和其它插件的发言 | 不受此开关控制 |

授权后，在同一页选择接话、找人、早晚问候、日程及事件发言，并设置每日联系保护上限。重新开启全局开关不会强制打开单独关闭的来源。文本、图片、戳一戳和插件自主工具/指令调用遵循相同边界；排队内容和打字等待后的分段发送会重新核验。正常回复仍遵循 AstrBot 的唤醒规则。

「现场接话」只需开关和参与程度，不再设置最低消息数、固定插话冷却或孤独阈值，也不扣找人额度。找人额度、留白与无人回应保护集中在 **自主发言细节 → 主动找人的保护**；统一后台预算在 **生活与作息 → 后台预算**。跨生活主题的「手感」滑块保留在基础页，不再另设群聊活跃度滑块。任何频率设置都不会授予白名单权限。

## 编辑范围

配置保存后会立即生效。编辑器复用已读取的工具列表，全局加载避免重复传输同一份世界配置；独立配置仍包含全局继承基线。配置历史只缓存文件元数据，按需读取快照正文，保留 50 条滚动与恢复规则。

若服务器连简单接口也长时间无响应，应同时检查 AstrBot 的事件循环诊断。第三方日志采集在主线程处理含图片数据的巨型 DEBUG 模型请求日志时，会拖慢整个面板；可将日志采集等级调到 INFO，并保留敏感信息脱敏。

顶部两个选择器各有用途：

- **会话**：观察与操作对象，例如查看状态、记忆、事件，或手动运行一条日程。
- **编辑范围**：地图、动作库、日程与设置保存到哪里。默认选择「全局默认」。

选中一个会话后，未独立的页面显示「继承全局」且只读。勾选「本页单独配置」，
以当前生效配置为起点修改，再点保存。生成区域、动作或日程得到的草稿也保存到当前编辑范围。
切换范围前如果有未保存修改，会提示是否放弃；取消后可以先保存。

顶栏的**自主发言**统一暂停全部自主发言；各来源的开关进一步限制已获授权的会话：

| 开关 | 关掉之后 |
| --- | --- |
| 自主发言（顶栏） | 暂停全部自主发言，包括日程与事件；别人叫她照常回 |
| 日程到点也发言 | 日程照常执行动作链，只是不把话发出去 |
| 事件发生时发言 | 事件照常推进、照常记录，只是她不为这件事开口 |

**范围说明**（顶栏最右）里是「本页单独配置」和继承说明；切到某个会话时会自动展开，
其余时间收着，顶栏始终只有一行高。地图页的顶栏不显示会话选择器——
那里用地图工具栏上的会话筛选，看的是「她此刻在哪个区域」。

| 配置块 | 包含内容 |
| --- | --- |
| 地图 | 区域、地点、区域内连线与跨区连线 |
| 动作库 | 全部动作及分组、已清除动作的记录 |
| 日程 | 完整日程列表和每条日程的目标、时间、动作链 |
| 设置 | 人格、世界规则、情绪、事件规则、记忆规则、作息、名片与其它通用世界设置 |

**独立的是整个配置块**。例如只独立动作库，地图和日程仍跟随全局；
之后全局新增动作，不会自动追加进已独立的动作库。需要协调地图和动作使用的地点，
以及日程引用的动作 ID；保存时出现的配置提醒应一并检查。

取消「本页单独配置」并保存，会移除该块的独立版本，恢复使用最新全局配置。
这不会合并两个版本，也不会删除角色的位置、记忆或生活状态。写入前会保留配置历史。

管理员、全局暂停、自主发言白名单、生活分享白名单、会话与共享生活组管理、配置预设和恢复默认等管理功能仍属于全局。
已发生的事件、记忆与状态是运行数据，不通过配置继承互相复制。
插件详情中的模型槽位与基础运行参数也仍是插件级设置。

## 共享生活组

已编入共享生活组的群和私聊代表同一个角色，因此一起使用**组主会话**的配置。
编辑范围会将它们显示成一个会话组，生活时钟与日程只推进一次。
暂时停用主会话不会把配置切换成另一个成员的版本。

成员在入组前已有的独立配置仍保留；在组内暂不使用，离组后重新生效。
修改组主会话会更换配置来源。需要每个群独立地图与日程时，应保持它们为独立会话。

生活共享不合并各会话的关系与好感。人物档案、原生事实、交谈日期、好感额度与关系身份按实际群或私聊分别保存，结构化字段仍遵循自己的共享规则。独立的“关系与好感”页始终按 QQ 汇总，不受其他页面所选编辑范围影响；统一保存只是应用一次共同起点，后续变化仍然各算各的。

## 日程示例

所有群都用同一套作息：在「全局默认 → 日程」里修改，其它会话保持继承。
只有 A 群作息不同：选择 A 群，进入日程，勾选单独配置并保存。
此后 A 群使用自己的整套日程，其它会话继续使用全局日程。

Bot 自己添加、删除或回收一次性日程时，也会写回实际使用的那套日程：
继承者写全局库，独立会话写自己的库。日程的目标会话限制仍然有效；
全局库中的提醒若只想给某个群，应在该条日程中指定目标。
