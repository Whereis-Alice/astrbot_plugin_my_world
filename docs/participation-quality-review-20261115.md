# 主动接话质量审查（2026-11-15）

当前机制具备基本的对象识别、语义理解和自然收尾能力，关注时机与表达价值仍有局限，不能视作稳定理解全部群聊。

## 验证范围

使用本机当时实际配置的角色卡、生活快照和 `deepseek-v4.1-flash`，通过已安装的 AstrBot 4.29.4 Provider SDK 调用。合成群聊经过真实 `note_chat` 和共享参与提示词；模型结果使用正式严格解析器。没有向真实群发消息，也没有调用工具、改变角色配置或推进世界状态。

这测的是共享提示词和模型，未跑第三方原生请求 hooks、媒体理解及工具的完整生产链。原生消息和引用的首尾截取另有入口回归验证。

## 实际表现

- 16 个主批场景均返回有效协议。7 个明确旁听场景都选择 `listen`：另一机器人的专属任务、双人私聊、已经解决、要求安静、简单附和、长消息末尾收尾和旧引用点名。
- 8 个开放场景允许开口或旁听。模型能理解书页折皱后的“它”，换题后不继续原话题，新的问题引用新的来源，也没有把对另外两人的“你俩”认成自己。
- 对正文中的提示词注入，模型拒绝执行，没有泄露或工具动作；仍多说了拒绝台词，后台观察不必对此作答的分寸没有稳定掌握。
- 单独的首个预检曾只返回一句台词，缺少内心及意图。按生产的有限格式修复提示再调用，恢复有效决定并保留原台词；不能假定首次生成总符合协议。
- 对开口价值提示做了 4 个有限复测：电影话题从单纯“没看过呢”变成相关好奇提问，具体问题与轻松共鸣仍可开口。样本不足以证明稳定提升，提示词注入仍出现短拒绝。

## 仍存在的薄弱处

1. **理解话题不等于说得有意思。** 主批的电影回应只有“没看过呢”；对画作损坏的安慰偏复述，对半年练习后失误的回应稍偏“不甘心”，没有完全贴住羞愧或挫败。不能靠强制提问或强制安慰来补足。
2. **观察优先级仍主要依据词汇。** 没有共同词的语义续问可能只进入普通观察，因等待而过期；共享泛词也可能误取得较早机会。后续模型理解正确，不代表调度已能稳定识别语义。
3. **现场选择不是逐条完整阅读。** 大批消息按预算选取有限现场。`checked_seq` 表示本批已判断，不保证所有行进入模型；落选记录仍可在后续消息或引用中作为背景重现。不能为了补看每行而自动反复请求同一批。

本次修复长文末尾丢失、原生引用提前截断、无效引用退成无引用发言，以及已回应消息误给引用能力。这些是确定的输入与协议缺陷。参与程度、模型、白名单、正常直接回复及自主活动沿用原配置。
