# 资源与小内存服务器

[文档目录](README.md) · [生活沙盒](life-sandbox.md) · [返回首页](../README.md)

普通的日程、情绪、生活记忆和人物资料主要使用文本与 SQLite，My World 不会为这些功能加载另一套本地大模型。独立电脑、浏览器、图像处理和其他插件调用的程序，才更容易明显增加内存占用。

## 小内存服务器怎样用

- 先保留默认的一个后台工作、一个生活沙盒。它们分别控制后台工作并发和电脑环境名额；已有配置中的并发不会被升级强行覆盖，可在生活页的「节奏与预算」改成一。
- 没有编程或电脑操作需求时，关闭「允许自主生活使用独立沙盒」。日程、生活事项和世界内活动仍可继续，正常 QQ 聊天的电脑能力保持原样。
- 需要电脑时，可把沙盒服务放在另一台机器。与 AstrBot 同机部署的沙盒仍占本机内存；调用远程模型不等于电脑环境也在远程。
- 保留空闲回收。临时文件可能随环境回收而消失，重要成果需要另行保存。日程、生活记忆、事项进度和执行账本存放在插件数据目录，不随沙盒回收删除。
- 语义召回和生活重排都可以按需开启。它们默认关闭，普通关键词回忆仍能使用。没有必要为使用本插件额外安装本地嵌入模型。

AstrBot 当前 BoxLite 实现为每个实例配置 512 MiB；这是实例配置额度，不是实际常驻内存的实测值。浏览器、桌面、模型和媒体工具的占用因具体配置而异，因此没有一个适用于所有服务器的最低内存承诺。整套服务还需要给 AstrBot、QQ 适配器和其他插件留出空间。

## 怎样判断占用

系统显示的 AstrBot 进程内存包含宿主与所有插件，不能直接当成 My World 的占用。观察「可用内存」比只看 Linux 的「已用内存」更有用；文件缓存可由系统回收。

需要复现核心负担时，在插件目录中使用 AstrBot 的 Python 运行：

```sh
python tools/benchmark_resources.py --data-dir "插件数据目录" --rounds 100 --memory-mib 256
```

工具把世界配置与数据库复制到临时目录，在独立进程重复读取状态和检索生活记忆。它不修改原数据，不调用模型、不启动沙盒、不向聊天发送消息，退出时删除自己的临时副本。输出只有会话数量、耗时和内存读数。Linux 下还限制测试进程的地址空间；其他系统的内存读数可能显示为空。

这个测试覆盖核心状态与检索，**不代表完整插件或整个 AstrBot 只需同样的内存**，也不能替代持续运行、模型请求、人物画像和真实电脑负载的观察。不要把短时没有增长写成长期没有泄漏的保证。

## 已有的资源边界

语义检索先过滤会话范围，只读取候选的向量，每批最多十六条；只缓存相似度，短期保留十六次查询，过期项会清理。生活 Agent 接收当前步骤、已完成步骤状态和近期执行依据，完整账本留在数据库中供查看。日志与历史按各自保留数量滚动，后台工作去重、排队并受预算与超时限制。

生活沙盒关闭属于尽力回收，服务端可能延迟释放资源；旧 Shipyard 尤其依赖 TTL。插件不会为了省内存停止共享服务、杀掉未知进程、清理其他插件缓存或删除服务器其他目录。
