# 资源与小内存服务器

[文档目录](README.md) · [生活事项](life-matters.md) · [返回首页](../README.md)

日程、情绪、生活记忆和人物资料主要使用文本与 SQLite。My World 不加载另一套本地大模型，个人项目通过世界内活动和 AI 模拟推进，无需额外部署电脑环境。

## 小内存服务器怎样用

- 后台同时模型请求保留默认的一个。已有配置中的并发不会被升级强行覆盖，可在生活页的「节奏与预算」改成一。
- 设置适合自己的后台每日调用与 Token 预算，控制规划、复盘和整理频率。
- 安静翻消息默认关闭。开启后复用已有缓存与后台通道，默认每天最多三次、间隔两小时、每次最多二十条文字与三千字，不启动真实电脑环境；详见 [阅读范围与开销](chat-browsing.md)。
- QQ 聊天中的电脑和工具使用由 AstrBot 及相应插件管理，其启动的浏览器、媒体处理程序等仍会使用服务器资源。
- 语义召回和生活重排都可以按需开启。它们默认关闭，普通关键词回忆仍能使用。没有必要为使用本插件额外安装本地嵌入模型。

整套服务还需要给 AstrBot、QQ 适配器和其他插件留出空间。没有一个适用于所有服务器的最低内存承诺。

## 怎样判断占用

系统显示的 AstrBot 进程内存包含宿主与所有插件，不能直接当成 My World 的占用。观察「可用内存」比只看 Linux 的「已用内存」更有用；文件缓存可由系统回收。

需要复现核心负担时，在插件目录中使用 AstrBot 的 Python 运行：

```sh
python tools/benchmark_resources.py --data-dir "插件数据目录" --rounds 100 --memory-mib 256
```

工具把世界配置与数据库复制到临时目录，在独立进程重复读取状态和检索生活记忆。它不修改原数据，不调用模型或工具、不向聊天发送消息，退出时删除自己的临时副本。输出只有会话数量、耗时和内存读数。Linux 下还限制测试进程的地址空间；其他系统的内存读数可能显示为空。

这个测试覆盖核心状态与检索，不代表完整插件或整个 AstrBot 的最低内存需求，也不能替代持续运行、模型请求和人物画像负载的观察。

## 已有的资源边界

语义检索先过滤会话范围，只读取候选向量，每批最多十六条；短期保留十六次查询的相似度，过期项会清理。日志与历史按各自数量上限滚动；后台工作去重、排队并受预算与超时限制。生活模拟复用现有时钟，不为每个时间步调用模型。
