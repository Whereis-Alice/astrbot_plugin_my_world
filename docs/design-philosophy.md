# 设计理念

[文档目录](README.md) · [按主题拆开的详细说明](GUIDE.md) · [返回 README](../README.md)

## 一句话

**她在一个自己的世界里生活；说话和用工具都走 AstrBot 原生 Agent。**

插件负责"她今天在哪、在做什么、心里装着什么"，不负责替她开口、也不负责替她调工具。

## 三条边界

**1. 只注入，不接管**

`on_llm_request` 里只做三件事：门禁（这一轮要不要她回）、换人设（她的人设 + 世界规则，
替换宿主那份 persona）、加处境（状态 / 记忆 / 场景 / 虚拟动作写进 `extra_user_content_parts`）。
然后放行：宿主照常调模型、照常给工具、照常跑工具循环、照常发送。

为什么不全接管？因为"接管"意味着插件要自己维护工具清单、自己补参数、自己处理工具结果——
参数靠猜、工具一多就维护不过来，还会挡住 AstrBot 自己的工具循环。只注入就没有这个问题。

**2. 工具不归它管**

动作库里的动作不是"调用哪个工具"，而是她世界里能发生的事（虚拟动作 / 提示词事件）：
触发条件、事件文案、持续时长、状态影响。她要不要查资料、要不要发图，由原生 Agent 拿着
真正的工具清单在对话里决定。

旧版本里挂过工具的动作不会删：标成「旧版」、默认停用，配置原样留着，迁移期可以打开
`legacy_tool_actions` 临时恢复，之后按需改写成虚拟动作。

**3. 世界是未知的**

区域、日程、事件都可以让模型起草，但生成器只给**草稿**：先摆出来给用户改，确认才写进去。
生成前会读她的人设、已有区域 / 地点、区域连线与人际关系，所以新地方是"她会去的地方"，
不是随机地名。

她自己的规划来自世界时钟、日程、事件与回合复盘：到点了、条件满足了、你说了一件事，
都会变成她处境的一部分，下一轮说话时自然带着这段经历。

## 与"角色扮演插件"的区别

- 不是换皮回答机：她有地图、日程、数值、记忆与事件，经历会积累。
- 不是工具代理：她不代管 AstrBot 的工具，工具调用留在原生 Agent 里，参数与结果都走原路。
- 不是纯设定注入：设定（世界树那类）原样保留，她自己的状态与处境是**另外一层**，
  两个插件的注入互不覆盖。

## 取舍

- 主回复由原生管线发送，所以分段、引用、打字延迟交给输出增强插件（如 `outputpro_split`）；
  插件自己的主动发言仍然走它自己的发送路径。
- 回合复盘是"事后写账"：不会改她已经说出去的话，失败也只影响这一轮的状态记录。
- 旧版接管路径（`reply_mode=takeover`）保留为迁移兜底，后续版本会移除。
