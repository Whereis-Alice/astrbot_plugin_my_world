她有一张自己的地图、一套日常、会变的情绪和会积累的记忆。你不知道她今天会去哪个新地方、
会遇上谁、会不会把前一天的事记在心里——这个世界对你也**是未知的**。

但主回复不是"另一个大脑"在替她说话：插件只把**她是谁、现在在哪、什么心情、最近发生什么**
注入到请求里。调模型、跑工具、发送，全走 AstrBot 原生 Agent。

> 这个仓库是 [`astrbot_plugin_virtual_world`](https://github.com/exneverbur/astrbot_plugin_virtual_world)（作者 exneverbur）
> 的二次开发版，历史版本叫 `astrbot_plugin_her_world`。地图、动作、日程、数值、记忆、事件与编辑器的底子
> 来自原作者；v3 起改名成 **我的世界 MW**，并重做了"和原生 Agent 的关系"。请也给原仓库点个 star。

## 这个版本做了什么

| 方向 | 说明 |
| --- | --- |
| **不再抢工具** | 主回复交给 AstrBot 原生 Agent：工具清单、工具循环、工具结果续写、Provider 选择都不动，上百个工具照旧。 |
| **动作库重做** | 动作变成**虚拟动作 / 提示词事件**：她做什么、去哪里，只影响她的世界与提示词，不再挂工具、不再代执行。旧版工具动作自动标成「旧版」并停用。**默认动作按需启用**：新装只开说话 / 移动 / 睡觉等核心动作，其余在动作库里按需打开，「高级 → 启用默认动作…」可一键全部打开。 |
| **世界生成** | 编辑器里可以「生成区域」「生成日程」「生成事件」：先读她的人设、已有区域与**人际关系**，把草稿摆出来给你改，确认后才写进去。地图页还有**「一键重建地图」**：自选区域数、每区地点数与**每个地点顺带生成几个动作**（地点专属动作），可选填世界观主题等额外提示词，一次配好区域、地点、区内路线、跨区路线与配套动作，确认后替换当前地图；跨区路线会自动优先连接入口 / 门口类地点。**地图按区域分块生成**：一次只生成一个区域，弹窗里按顺序显示进度，后一块会读前面已经生成的区域与路线（不漏上下文），中途失败还能从断掉的那一块接着来；这样每个请求都短，不容易被反向代理的 100 秒（524）掐断。单个区域可以在区域属性里**「重做这个区域…」**：地点数 / 每个地点的动作数 / 额外提示词一次填完，还能选追加或替换现有地点。日程可以选**日常作息**或**一次性安排**（只做这一次，跑完自动删掉），还能开**「自动生成」**：每天到点自己排几条一次性安排；事件可以要**混合 / 好事 / 糟心事 / 怪事 / 日常**，默认就要求几种味道都有。动作库里既能**「按人设与地图生成动作」**，也能**「生成通用动作」**：不看人设，先铺一层普通人过日子都会做的小事（地图可选是否参考）；左侧分组菜单里有**「按地点」**一段，排序也能按地点。 |
| **地图工作台** | 地图占满整页：顶部悬浮工具栏、右侧可收起属性面板；滚轮 / 按钮 / 双击缩放，拖空白处平移，右下角可在**适应 / 填满**之间切换取景，⋯ 菜单里的**「重新铺开」**按当前窗口形状把区域（按路线力导）或地点（排网格）重排一遍。生成的整张地图会按窗口形状铺开，横竖都占满、不留半屏空白。路线标签默认智能防重叠，放不下的退成耗时小标签，悬停即可展开两端名字；可在 智能 / 全部 / 耗时 间切换。 |
| **上下文不丢** | 只追加、不替换：世界树的设定、helper_tools 的环境感知、记忆插件注入的上下文、其它插件往 `extra_user_content_parts` 写的内容都原样保留。 |
| **心思看得见** | 每轮一条「回合回执」：她说了什么、模型自己的推理（如果 Provider 返回）、用过哪些工具、这一轮的心情 / 好感 / 话题变化。左侧导航里还有一页**「内心活动」**：按时间倒序看她留下的每一句心里话，带时间、地点和来源（聊完一轮 / 自主决定 / 她想事情）。 |
| **兼容联动** | 与动态视觉、输出增强（分段 / 引用 / 打字延迟）、灵动名片、表情包、语音等插件按原生流程配合，互不抢钩子。她在聊天里（用别家天气工具）查到的天气会**自动记成世界天气**，写进提示词也画在地图横幅上，后台刷新自己认天气工具、不用配「工具型动作」。原[心迹画像](https://github.com/Whereis-Alice/astrbot_plugin_profile_weaver)的能力已经**真正并入通讯录**：一个联系人统一承载关系、称呼、备注、字段、历史、审计与多会话记录，原指令和三个 LLM 工具全部保留。 |
| **默认全局，可单独调整** | 地图、动作库、日程和设置默认继承全局；会话可按配置块独立调整。编辑范围与自主搭话常驻顶栏一行，本页单独配置与继承说明收在「范围说明」里；左侧导航可以收成一排图标。想让她彻底安静：顶栏「自主搭话」+ 设置里的「日程到点也发言」「事件发生时发言」三个都关掉（别人叫她仍然会回）。 |

## 它是怎么工作的

一次群聊消息的完整流程：

1. **门禁**：这个会话开没开、睡觉没有、这一轮要不要她回。不回就拦下，绝不让主人格顶上来。
2. **注入**：用她的人设 + 世界规则 + 当前场景替换宿主那份人设；把状态、记忆、最近发生的事、
   命中的虚拟动作写进 `extra_user_content_parts`（跟着用户消息走，不写进对话历史）。
3. **放行**：不调用 `stop_event()`。AstrBot 照常调模型、照常给工具、照常跑工具循环、照常发送。
4. **记账**：`on_llm_response` / `on_using_llm_tool` / `on_llm_tool_respond` / `after_message_sent`
   只做观察——把她说过的话写回世界、推进"回到哪一条"的水位线，并跑一次**回合复盘**：
   心情、好感、话题、心事、口吻都从这一轮真实对话里抽出来。

**明确不碰的东西**：`req.func_tool`（工具集）、`req.contexts`（对话历史）、Provider 选择、
别家插件写进 `system_prompt` 与 `extra_user_content_parts` 的内容。

## 装好之后

1. 在 AstrBot 插件市场 / 插件目录里安装本插件并启用。
2. 在群里发 `/mw session add`（或稍后在编辑器「会话」页添加）。只有白名单里的群 / 私聊会启用。
3. 打开 **AstrBot 面板 → 插件 → 我的世界 MW → 我的世界编辑器**：
   - 「设置 → 她是谁」：选择她的人设（也可以直接用 AstrBot 当前会话的人设）。
   - 「地图」：先有区域，再有地点；可以点「生成区域…」让模型按人设起草。
   - 「日程」：可以点「生成日程…」排一版日常。
   - 「事件」：可以点「生成事件…」挑一件事投给她。
4. 发条消息试试：`/mw status` 看她现在在干嘛；编辑器「控制台」页可以手动推进 tick，几分钟看一天。

## 动作库 = 虚拟动作

动作库里的条目不再是"调哪个工具"，而是**她世界里能发生的事**：

- 触发：手动 / 定时 / 关键词 / 场景条件（地点、时段、星期、状态）/ 事件链 / 概率；
- 内容：事件文案（这件事发生时，用她的视角写进提示词的那句话）、可选口吻、持续时长；
- 效果：移动、状态增减、名片文案、标记位或记忆、触发后续事件；
- 约束：冷却、每日上限、只做一次、限定会话或群。

她做什么由**她自己规划**：世界时钟到点、条件满足、你投递了一件事，都会变成她处境的一部分，
下一次说话时她自然带着这段经历。

旧版本里挂过工具的动作不会丢：升级后它们会显示成「旧版」，默认停用，配置原样保留，
可以按需改写成虚拟动作。想一次性清干净就发 `/mw action purge`（两步确认，连同空分组一起清），
或者在编辑器「动作库 → 高级 → 清除旧版动作…」里点两下。工具调用请交回 AstrBot 原生工具 / 定时任务。

## 全局配置与自主搭话

编辑器顶部的 **全局自主搭话** 开关立即生效，覆盖所有群与私聊，包括以后添加的会话。
关闭后，她不再自主找人、插话或发送自主动作续说；**日程提醒、事件发言、正常消息回复仍保留**，
走动、休息、情绪和心思也继续推进。这只控制本插件的自主发言，不控制其它插件的消息。

「设置 → 说话与决策」里的**主动说话频率滑块最低档不是关闭**：它只是把上限压到很低，
她仍可能偶尔主动开口。要完全停下自主搭话，请用上面的全局开关。

**编辑范围** 默认是「全局默认」。想让某个群使用自己的动作库或日程：选中该会话，进入相应页面，
勾选「本页单独配置」，修改后保存。地图、动作库、日程、设置分别继承，互不强制绑定。
没有勾选的块会持续跟随全局更新；已经独立的块保留自己的完整配置。取消勾选并保存即可恢复继承。

「会话」选择器决定查看谁的状态、日志与事件；「编辑范围」决定修改谁的配置。
已有**共享生活组**的成员共用组主会话的配置与生活，不会因换一个群说话就切换地图。
详细规则、配置块范围与日程示例见 [全局与会话配置](docs/configuration.md)。

## 和这些插件怎么配合

| 插件 | 配合方式 |
| --- | --- |
| [动态视觉 motion_vision](https://github.com/Whereis-Alice/astrbot_plugin_motion_vision) | 动图 / 视频的帧解读、`image_urls` 与它写进请求的内容一个字都不动；本插件只追加自己的处境块。 |
| [输出增强 outputpro_split](https://github.com/Whereis-Alice/astrbot_plugin_outputpro_split) | 主回复由原生管线发送，分段、智能引用、打字延迟都交给它；本插件不抢发送。 |
| 灵动名片 dynamic_card_plus | 开着它时群名片由它接管，本插件不抢；它没接管的状态由本插件按世界状态更新。 |
| helper_tools | 环境感知等临时上下文原样跟着请求走，本插件不再复制一遍。 |
| worldtree_lore | 世界树写进 `system_prompt` / `extra_user_content_parts` 的设定保留；每个会话临时切换模型也照常生效。 |
| meme_magpie / genie_tts_llm | 表情包与语音在原生回复钩子里挂到主回复上，不再需要本插件桥接。 |
| 记忆 / 上下文类插件 | 只追加、不替换：请求里的历史与注入内容都保留。 |

## 从旧版本迁移

- **数据**：本插件使用自己的数据目录。想搬 `astrbot_plugin_her_world` / `astrbot_plugin_virtual_world`
  的数据，可以设环境变量 `MY_WORLD_MIGRATE_FROM=<旧数据目录>`，插件第一次启动时会整份复制（不覆盖已有数据）。
- **旧接管**：配置项 `reply_mode=takeover` 可以临时回到"插件自己调模型自己发"的旧路径，
  仅作迁移兜底，后续版本会移除。
- **旧工具动作**：默认停用；确实还需要旧行为时打开 `legacy_tool_actions`
  （或环境变量 `MY_WORLD_LEGACY_TOOL_ACTIONS=1`）。建议尽快把这类动作改写成虚拟动作。

## 常见问题

**Q：为什么她不调用我装的工具了？**
工具仍然在，只是不再由本插件代调。主回复走原生 Agent，模型会在需要时自己调用；
本插件不再裁剪工具集，也不会再出现"参数猜错"。

**Q：会不会丢别的插件给的上下文？**
不会。注入模式只替换宿主那份人设，其它内容原样保留；测试里覆盖了 helper_tools 的环境感知、
世界树设定、动态视觉的帧解读与图片、以及 `extra_user_content_parts` 里的所有内容。

**Q：会不会又出现重复回复？**
主回复只有原生管线发送一次；本插件在注入模式下不再自己发送。旧版接管模式才会有两套发送逻辑，
所以默认不启用。

**Q：她的心思在哪看？**
编辑器「控制台 / 日志」里的 `reflection` 事件，包含 `env / state / mood / who / inner / intent`
与这一轮的心情、好感、话题变化；如果模型自己返回了推理内容，也会一起记下来。

**Q：需要配哪几个模型？**
主回复模型由 AstrBot 原生流程选择。编辑器生成区域、地点、动作、日程和事件使用插件配置中的
「内容生成模型」，留空时复用「插件用模型」，再回落到会话默认模型。
「打杂模型」负责复盘等后台任务，「看图模型」按需配置。

**Q：点击生成区域、日程或事件后没有反应？**
请升级到 v3.0.3 或更新版本并重新打开编辑器。生成成功后预览被立即关闭的问题已修复。
生成时按钮显示「生成中」，窗口显示已等待的秒数；成功后保留可编辑的草稿，确认前不会保存或投递。
失败原因会留在窗口内，可以直接重试。模型未配置、连接失败、额度不足、空回复和格式不符合要求
都会显示相应提示；生成超过「生成超时（分钟）」才会中止（默认 10 分钟，内容多时几分钟是正常的；
可以在插件配置里调大，填 `0` = 不超时）。检查模型时，优先查看插件配置中的
「内容生成模型」；留空则复用插件用模型，再回落到会话默认模型。

**Q：动作库里那一堆「旧版」动作怎么清掉？**
发 `/mw action purge` 先看会删哪些（含涉及的分组），确认后发 `/mw action purge confirm`；
也可以在编辑器「动作库 → 高级 → 清除旧版动作…」里点两下清完。清除过的 id 会记进
`purged_actions`，以后即使打开旧版开关也不会复活。

**Q：群名片一直显示以前改过的名字？**
v3.0.1 修了。控制台现在会读**平台上的真实名片**（dynamic_card_plus 改过也跟得上），
「保存名片」也只改当前名片、不再顺手覆盖「原名」。升级后打开控制台刷新一次，名字就会对齐。

**Q：两个人同时 @ 她，会被合并成一条回复吗？**
不会。连发合并只并**同一个人**在短时间内的几句（她才不会答一句、再答一句）；
不同人几乎同时触发时各回各的，第二条消息不会被吞掉，也不会被算进别人的那一轮。

## 开发与测试

```powershell
python -m pytest -q
```

代码结构：`main.py` 只做编排（钩子、指令、生命周期与接线）；`core/` 放领域逻辑（世界模型、提示词、
状态、记忆、事件），其中 `core/engine/` 是引擎本体（`MyWorldEngine` 由一组按职责拆分的 mixin 拼成）；
`adapters/` 是宿主绑定（模型 / 看图 / 指令 / 发送 / 工具 / 人设）；`web/` 是编辑器接口与访问密码；
`pages/world_editor/` 是网页编辑器；`tests/` 是不依赖 AstrBot 的回归测试。
